# RoBoard 多智能体指挥舱 MVP 计划

> 语言：中文
> 架构风格：多 Docker 服务拆分（前端/后端/Agent 管理/Redis/MCP/网关）
> 目标用户：内容创作者
> 任务创建：一句话直接跑（LLM 默认开启）
> 执行：自建单机 + Playwright/Playwright MCP
> 通知：Email / Web 前端通知
> 触发：手动 + 定时
> 3D 风格：极简但高级

---

## 1. 目标与范围

### 目标（MVP必须达成）
- 用户用“一句话”创建任务，系统可自动规划与执行。
- 任务执行过程以 WebSocket 事件流实时可视化（3D房间 + 任务进度面板）。
- 任务完成后产出可复用资产：结构化结果 + 关键帧 + LLM 总结 + Email/Web 前端推送。
- 遇到验证码/2FA/高风险动作时进入 human-in-the-loop（暂停并提示用户）。
- 系统具备可扩展的多服务容器化部署方式。

### 已确认决策（根据你最新说明更新）
- 前端定位：游戏化是“更友好的界面”，不做真实游戏玩法与无效交互。
- 执行依赖：任务执行需 MCP 支持，**当前仅接入 searxng**（workspace 中已有镜像）。
- 域名策略：**不设 allowlist，使用 IP 代替域名**。
- 多租户：**第一版即多租户**，每租户并发上限 **2**。
- 资产保留：**长期保留**（暂不做清理）。
- 推送渠道：**仅邮件 + Web 前端通知**（接口需可复用到 Godot）。

### 明确不做（硬护栏）
- 不做多人实时3D协作。
- 不做用户导入Playwright脚本/DSL。
- 不做复杂工作流编排（分支/循环/拖拽图）。
- 不做自动绕过验证码/2FA。
- 不承诺“可重跑一致性”（只做“可视化回放 + 结构化产物”）。
- 不做真实支付闭环（仅价格墙与配额锚点）。

---

## 2. 核心体验与差异化

### 体验闭环（Wow-factor）
1. 一句话创建任务 → 立即返回任务编号与预计时长。
2. 3D 代理进入“工作”动画 → 实时展示任务步骤与进度。
3. 任务完成 → 生成“回放资产包”（事件时间线 + 关键帧截图 + 结构化结果）。
4. LLM 默认总结 → 通过 Telegram / Email 推送任务摘要。

### 差异化叙事
- 不是表格式日志，而是“可回放的自动化关卡”。
- 任务执行结果可资产化与复用（回放 + 结构化结果）。
- 3D 作为系统状态与瓶颈的“空间可视化”承载。

---

## 3. 关键架构与服务拆分（Docker）

### 服务列表（多容器）
- **web-frontend**：React/Vite + Three.js 或 R3F（3D 视图）
- **api**：FastAPI（鉴权/任务管理/事件流/通知编排）
- **dispatch**：任务执行编排（LLM规划/步骤拆解/队列）
- **worker-playwright**：Playwright 执行器（或 Playwright MCP 代理）
- **mcp-server**：Playwright MCP 服务
- **searxng**：搜索服务（当前唯一接入的 MCP 任务来源）
- **redis**：任务队列、速率限制、会话状态
- **gateway**：Nginx/Traefik（统一入口/路由/SSL）

### 进程隔离原则
- API 不直接执行 Playwright；执行由 worker 独立进程承担。
- LLM 规划与执行解耦；规划结果写入任务步骤流。
- MCP 服务独立，便于未来扩容。
- 多租户资源隔离通过“租户并发上限=2”硬限制保证。

## 4. 任务创建与执行模型

### 任务创建（“一句话直接跑”）
- 输入：用户描述 + 目标站点 + 输出格式 + 频率（可选）
- 输出：任务计划（步骤列表）+ 估算时长

### 事件流协议（WebSocket）
- 关键事件：
  - `task.created`
  - `task.step.started`
  - `task.step.progress`
  - `task.step.artifact`
  - `task.requires_input`
  - `task.completed`
  - `task.failed`

### Human-in-the-loop
- 触发条件：验证码/2FA/支付/表单提交/发送/删除动作
- 行为：暂停任务 → 前端提示 → 用户确认后继续

---

## 5. 回放资产与结果交付

### 资产内容
- 事件时间线（JSON）
- 关键帧截图（可选，默认开启）
- 结构化结果（JSON/CSV）
- LLM 总结（Markdown）

### 推送策略
- 邮件/Web 前端推送：仅任务级摘要（开始/需要介入/完成/失败）
- 防刷屏：同一任务只发 1-2 条关键消息

---

## 6. 安全与隐私（硬护栏）

- 凭据不进入日志/回放；敏感字段默认脱敏。
- 回放资产默认“可分享版本”与“内部版本”分层。
- 明确禁止用途（绕过验证码/批量抓取敏感个人数据等）。
- 资产长期保留时，需支持最小可见范围与租户级隔离。

## 7. MVP 功能清单（按优先级）

### P0（必须完成）
- 一句话创建任务（自然语言 → 步骤）
- WebSocket 实时事件流
- 3D 场景 + 代理状态机
- Playwright/MCP 任务执行（当前仅 searxng）
- LLM 总结 + Email/Web 前端推送
- 人工介入点

### P1（可选增强）
- 任务回放时间线 UI
- 任务模板库（作为引导，不强行限定）
- 基础成就/等级

## 8. 验收标准（可命令验证）

- Healthcheck
  - `/health` 返回 `ok`
- 创建任务
  - `POST /api/tasks` 返回 `task_id`
- WebSocket 事件流
  - 至少收到 `task.step.started` 和 `task.completed`
- 执行结果
  - `GET /api/tasks/{id}/result` 返回 `summary + artifacts + structured_output`
- Human-in-the-loop
  - 触发后任务状态为 `needs_human`
- 通知
  - `GET /api/tasks/{id}/notifications` 至少 1 条成功投递记录（邮件或Web前端）

---

## 9. 风险与降级策略

| 风险 | 影响 | 降级策略 |
|------|------|---------|
| CAPTCHA/2FA | 任务失败率高 | 直接进入 human-in-the-loop |
| LLM 误操作 | 不可控 | 高风险动作必须确认 |
| 反爬/风控 | 执行失败 | 降级为只读模式 |
| 成本波动 | 不可控 | 并发+时长+token 预算硬限制 |
