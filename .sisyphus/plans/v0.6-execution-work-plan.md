## Context
### Original Request
- 把当前 `README.md`、`docs/prd/2026-03-15-linpo-v0.1-observer-prd.md`、`docs/architecture/2026-03-15-observer-architecture.md` 与 active `.sisyphus` 计划收敛为真正可由 `/start-work` 使用的 v0.6 可执行文档链。

### Interview Summary
- `docs/` 与 `.sisyphus` 中相关计划文档都要同步更新，避免执行计划与真源脱节。
- 用户补充：`overview` 是概览页，展示用户全部 agents；`topology` 展示实例、agents、skills、外接 ACP 等关系并承担配置调整；新增 `kanban` 作为主导航视图，用于聚合工作项、协作状态与关键工作信号；三个页面都允许点入 agent 对话页；`session/:instanceId/:agentId` 是 drill-down route，不作为侧边栏视图。
- v0.6 主侧边栏承载 `overview`、`topology` 与 `kanban`，底部保留用户信息入口。
- 会话消息历史需要支持 Markdown 渲染；工具调用不再展示原始 JSON，而要折叠为一条调用说明，并使用不同的消息气泡样式。
- `visual-engineering` 更适合设计，不承担最终编码、测试、部署闭环；相关任务需将设计与实现 owner 分离。
- 首页汇报感禁止额外 prompt 注入，不允许通过静默向 agent 发送 prompt 来制造汇报内容。
- topology 首期动作环固定为 `查看 / 进入 / 配置 / 关系`，同屏仅单开；不支持 drill-down 的节点禁用“进入”，且首期不暴露 pause/reset/send/delete 等 destructive/runtime controls。
- 部署与 ravin Playwright 不等到最后统一调试，而是在每个 major feature 完成后重复执行；测试范围不仅覆盖改动功能本身，也覆盖强相关功能链路。
- 后端新增或修改的核心逻辑必须有完整单元测试覆盖，不能只靠集成测试兜底。
- 全部任务完成后，必须从头逐条核对实现成果是否符合 active plan / PRD / architecture；若仍有偏差，继续补齐并重新核对后才可宣告收口。

- 明确排除控制面扩张、模板系统重构、会话持久化大改。

## Work Objectives
### Core Objective
- 交付一个与当前 `docs/` 及 `.sisyphus` 计划文档一致的 v0.6 观测入口：`overview`、`topology` 与 `kanban` 作为主导航视图，其中 `overview` 负责展示用户全部 agents 并承担概览与巡视优先级，`topology` 负责实例 / agent / skill / ACP 关系与配置表达，`kanban` 负责聚合工作项、协作状态与关键工作信号，且三页都允许进入 agent 对话；`session/:instanceId/:agentId` 作为非侧边栏的单 agent drill-down route；同时完成会话消息历史的 Markdown 渲染与工具调用摘要样式收口。

### Deliverables
- 文档真源修订：把用户新确认的 overview/topology/kanban/sidebar/drill-down 语义、三页进入 agent 对话约束、消息历史展示约束、分阶段部署验收与最终逐条核对要求落盘到当前 `docs/` 与 `.sisyphus` 相关计划文档。
- 新增后端聚合 API 与拓扑 API，并补上 diagnostics / freshness / request_id 语义。
- 前端 overview/topology/kanban 页面基于新聚合契约重建，并保留到 session 的明确入口。
- 会话消息历史支持 Markdown 渲染，并把工具调用展示改为摘要说明气泡而非原始 JSON。
- 前端 HTTP / WS 客户端与 session 页面完整贯穿 `instanceId`。
- 后端新增或修改的核心逻辑补齐完整单元测试覆盖。
- 每个 major feature 完成后都完成部署、强相关功能集成验证与 ravin Playwright 浏览器级验收。

- `python -m pytest tests/unit -q` 中与本次新增/修改后端核心逻辑相关的测试全部通过。

### Must Have
- `overview` 默认 landing，且登录默认回跳到 `/overview`。
- `overview` 以用户全部 agents 为默认概览对象，并承担概览 / 巡视入口。
- `overview`、`topology` 与 `kanban` 都有明确的 agent 对话 drill-down 入口。
- `topology` 同时承担关系表达与配置入口，但不抢占默认 landing 角色。
- `kanban` 作为主导航视图承载聚合工作项、协作状态与关键工作信号，不偷换成审批中心或通用任务平台。
- 会话消息历史支持 Markdown 渲染。
- 工具调用消息显示为摘要说明气泡，而非原始 JSON dump。
- `instanceId + agentId` 是 session URL 的唯一真源；`/session` 与 `/session/:instanceId` 仅作为兼容重定向入口，不承载长期状态。
- topology 首期动作环固定为 `查看 / 进入 / 配置 / 关系`，同屏仅单开；不支持 drill-down 的节点禁用“进入”。
- overview 的部分失败场景必须保持页面可读，不允许把 partial visible 伪装成 empty-success。
- zero-agent 实例需要以明确文案进入 watchlist / 值得巡视对象，而不是误判为异常失败。
- 聚合 API 显式返回 `request_id`、freshness、partial failure / diagnostics 信息。
- taxonomy 在 docs、backend、frontend 三处统一。
- 全部任务完成后，必须逐条核对实现成果与 active plan / PRD / architecture 的一致性。

### Must NOT Have (guardrails, AI slop patterns, scope boundaries)
- 不新增写操作主线，不把 `OperatorAdapter` 变成 v0.6 主适配器。
- 不实现模板系统、模板选择器、动态多视图平台能力。
- 不做控制面扩张或工作流平台化改造。
- 不把 `overview` 改成告警中心、审计台或工作流中心。
- 不把 `kanban` 扩张成完整审批/治理/项目管理平台。
- 不用假数据掩盖真实失败；OpenClaw 不可用时必须显示明确降级/错误态。
- 不把未来视图扩展做成当前版本的侧边栏大重构；仅做可扩展配置，不做完整平台骨架。
- 不在消息历史中直接向用户暴露原始工具调用 JSON。
- 不通过静默向 agent 发送额外 prompt 来制造首页汇报感。
- 不在 topology / session 主路径暴露 pause/reset/send/delete 等 destructive/runtime controls。

## Verification Strategy
> ZERO HUMAN INTERVENTION — all verification is agent-executed.
- Test decision: tests-after + existing `pytest` / `vitest`; 对新增聚合契约优先先写失败测试再实现。
- QA policy: 每个任务都含 agent-executed 场景；页面任务可先由 `visual-engineering` 产出设计方向，但实际编码、测试、部署需由其他 agent 完成；每个 major feature 完成后必须立刻部署并执行 ravin Playwright 集成验证。
