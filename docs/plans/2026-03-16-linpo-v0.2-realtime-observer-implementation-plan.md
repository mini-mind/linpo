# Linpo v0.2 Realtime Observer Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在保持 observer-only 边界与现有 HTTP 只读契约不破坏的前提下，为 Linpo 交付“实时列表/实时详情/短时增量补发/失败回退全量”的 v0.2 最小闭环。

**Architecture:** 基于现有 v0.1 的 3 个 HTTP 只读接口继续承担首次加载、重同步 fallback 与排障入口；新增后端内存态、短时事件缓冲与浏览器 WebSocket 增量订阅通道。前端在列表页与详情页采用“先拉快照，再订阅增量；恢复失败则触发 resync_required 并重拉 HTTP 快照”的模型，不引入控制面、长期历史存储或复杂 ACK 机制。

**Tech Stack:** FastAPI、Python websockets client、React、TypeScript、Vite、pytest、前端现有测试脚本。

## 2. v0.2 最小交付目标

本阶段只交付一个升级后的 observer 闭环：

1. 列表页在首次 HTTP 快照之后可实时接收 agent 摘要更新
2. 详情页在首次 HTTP 快照之后可实时接收 topology 与节点事件增量
3. 浏览器短暂断线后可带 `last_seq` 进行短时增量补发
4. 当补发窗口失效时，后端显式发出 `resync_required`，前端回退到 HTTP 全量快照重同步
5. OpenClaw 上游失败仍显式暴露，不静默伪装成功
6. 保持 observer-only，不增加任何控制按钮、运行控制 API 或完整日志平台语义

如果以上 6 点不能同时成立，就不应继续扩张更复杂的频道、持久化事件流、多 agent 团队视图或控制面能力。

---

## 3. 实施原则

- 先守住 v0.1 HTTP 契约，再叠加实时能力
- 先做后端标准事件与状态流，再做浏览器通道
- 先做最小频道，再做前端订阅与恢复
- 先覆盖恢复/失败路径，再扩展 UI 细节
- 保持 YAGNI：v0.2 只做内存 buffer，不引入 Redis / Kafka / DB 事件仓库
- 不引入 ACK 协议、复杂订阅管理、控制面或长期历史回放

### 阶段 B：后端实时状态内核

**目标**：在不破坏现有 HTTP 读取接口的前提下，补齐标准事件、内存态与短时事件缓冲。

**需要实现的能力**：
- 定义后端内部标准事件模型
- 新增 `ObserverStateStore` 维护列表摘要、agent 详情拓扑、节点最近事件视图
- 新增 `ObserverEventBuffer` 按频道维护 ring buffer 与 `seq`
- 将现有 stub / openclaw 数据源变化统一映射为标准事件并驱动 state store
- 保持现有 `GET /agents`、`GET /agents/{agent_id}`、`GET /agents/{agent_id}/nodes/{node_id}` 输出结构不破坏

**完成标准**：
- 现有 HTTP 接口测试继续通过
- 新增单元/集成验证，证明标准事件可更新内存态与 buffer
- 每频道可按 `last_seq` 查询缺失增量，若超出窗口则返回“需重同步”语义

---

### 阶段 C：浏览器 WebSocket 通道

**目标**：为浏览器提供最小只读实时订阅通道。

**需要实现的能力**：
- 新增浏览器 WebSocket endpoint
- 支持订阅 `agents:list` 与 `agent:{agent_id}:detail`
- 订阅成功后发送 `snapshot_ready`
- 浏览器重连时接收 `last_seq`，尽力补发 buffer 区间内的消息
- 无法恢复时发送 `resync_required`
- 上游断连或通道异常时发送只读 `error`

**完成标准**：
- 能通过测试验证初始订阅、增量推送、带 `last_seq` 的恢复、恢复失败路径
- 不要求前端 ACK，不要求多频道复合订阅，不引入外部消息中间件

---

### 阶段 D：前端实时订阅与状态收敛

**目标**：让现有列表页与详情页在保留 v0.1 HTTP 主路径的前提下支持实时增量。

**需要实现的能力**：
- 列表页：先 `GET /agents`，再订阅 `agents:list`，增量更新 agent 摘要
- 详情页：先获取 agent detail/node detail 快照，再订阅 `agent:{agent_id}:detail`
- 在 UI 上显示“实时中 / 已断线 / 重同步中 / 错误”最小状态
- 收到 `resync_required` 后回退到已有 HTTP 加载流程
- 节点事件区支持实时追加，不扩张为完整日志控制台

**完成标准**：
- 前端 build 与现有测试通过
- 可通过新增测试或受控联调证明列表/详情都能正确消费增量
- 不新增控制按钮、筛选大盘或复杂运维交互

---

### 阶段 E：验证与联调收敛

**目标**：证明 v0.2 的实时 observer 闭环成立，并把失败路径纳入验证范围。

**必须覆盖的验证场景**：
1. 列表页首次加载 + 实时摘要更新
2. 详情页首次加载 + 拓扑变化更新
3. 节点事件实时追加
4. 浏览器短暂断线后利用 `last_seq` 补回增量
5. buffer 失效后收到 `resync_required` 并回退 HTTP 全量同步
6. OpenClaw 上游异常时前后端都显式暴露失败态

**完成标准**：
- 自动化测试覆盖关键契约与恢复路径
- runbook 可指导一次本地或联调演示
- 文档、接口、UI 文案中的术语保持一致

## 5. 推荐实现顺序

1. 先冻结最小实时消息协议与频道约束
2. 再做后端标准事件 / state store / event buffer
3. 再暴露浏览器 WebSocket endpoint 与恢复逻辑
4. 再接前端列表页与详情页实时订阅
5. 最后补恢复场景测试、runbook 与联调收敛

## 6. 第一批执行块

### 执行块 1：后端实时事件与状态缓冲骨架

**目标**：在后端补齐实时 observer 的内部基础设施，但暂不接浏览器 UI。

**建议文件**：
- `app/services/observer_data.py`
- `app/services/openclaw_client.py`
- `app/domain/` 下现有模型文件或新增实时事件相关模型文件
- `tests/` 下新增后端单元/集成测试文件

**完成标准**：
- 定义标准事件结构
- `ObserverStateStore` 可由事件驱动更新列表/详情快照
- `ObserverEventBuffer` 可按频道记录 `seq` 与有限窗口消息
- 现有 HTTP API 仍能从最新内存态提供快照

### 执行块 2：后端浏览器 WebSocket 只读通道

**目标**：交付浏览器可用的最小实时订阅接口。

**建议文件**：
- `app/main.py`
- `app/api/agents.py` 或新增 websocket 路由文件
- `app/api/schemas.py` 或新增实时消息 schema 文件
- `tests/integration/` 下新增 websocket 相关测试

**完成标准**：
- 支持订阅列表频道与详情频道
- 支持 `last_seq` 恢复与 `resync_required`
- 上游异常时返回显式 `error`

### 执行块 3：前端列表页与详情页实时化

**目标**：让现有页面消费实时增量并提供最小恢复反馈。

**建议文件**：
- `frontend/src/api/client.ts`
- `frontend/src/main.tsx`
- `frontend/src/components/AgentList.tsx`
- `frontend/src/components/AgentDetail.tsx`
- `frontend/src/components/TopologyTree.tsx`
- `frontend/src/components/NodeDetailPanel.tsx`
- `frontend/tests/` 下新增前端测试

**完成标准**：
- 列表页可实时更新 agent 摘要
- 详情页可实时更新 topology 与 node events
- `resync_required` 可触发回退 HTTP 重拉
- UI 仅增加观测状态提示，不增加控制能力

### 执行块 4：OpenClaw realtime adapter 与增量摄取

**目标**：在不改变浏览器协议的前提下，把 OpenClaw 的真实增量变化接入后端 observer 状态内核。

**建议文件**：
- `app/services/openclaw_client.py`
- `app/services/observer_data.py`
- 如有必要，新增 `app/services/openclaw_realtime.py`
- `tests/` 下新增 openclaw realtime adapter / ingest 相关测试
- `tests/integration/` 下补 websocket + openclaw data source 相关测试

**实现边界**：
- 保持 Linpo 现有浏览器协议：`snapshot_ready` / `agent_summary_updated` / `topology_updated` / `node_events_appended` / `resync_required` / `error`
- 不引入 Socket.IO 到 Linpo 浏览器侧
- 不暴露 OpenClaw 原始事件形状到前端
- 采用“adapter/plugin 边界”：OpenClaw 原始消息先进入 adapter，再映射成 `ObserverRealtimeEvent`，最后驱动 `apply_event()` 与 buffer
- OpenClaw 若仅能提供有限增量语义，可接受先实现最小事件集（agent summary / topology 基础变化 / node event append），不足部分继续显式失败

**完成标准**：
- `data_source=openclaw` 时，后端不再只支持 snapshot handshake，而能持续消费最小增量事件
- `/ws/observer?data_source=openclaw` 至少能对一个真实 agent 频道提供增量更新
- 现有 replay / `last_seq` / `resync_required` 语义继续由 Linpo 自己的 buffer 提供
- 上游中断时仍向浏览器显式发送 `error`

#### 执行块 4A：OpenClaw `agents:list` realtime 首刀

**目标**：先打通最小真实频道，让默认列表页可消费 OpenClaw 的 agent summary 增量。

**边界**：
- 仅支持 `agents:list`
- 复用 Linpo 现有浏览器协议与 buffer
- 允许前端仅对 `openclaw + agents:list` 放行，detail 频道继续显式拒绝
- 必须使用共享长生命周期 data source，避免每次请求重建状态内核

**完成标准**：
- `AgentsList` 默认 `openclaw` 路径可建立 realtime 订阅
- `/ws/observer?data_source=openclaw` 可发送 `snapshot_ready` 与 `agent_summary_updated`
- `last_seq` / `resync_required` / 上游失败显式 `error` 均通过测试验证

#### 执行块 4B：OpenClaw `agent:{agent_id}:detail` 最小接入

**目标**：在不引入完整 OpenClaw 领域建模的前提下，让详情页最小消费 topology 与 node events 增量。

**边界**：
- 继续复用 `agent:{agent_id}:detail` 频道与既有前端消费逻辑
- 仅映射最小事件集：
  - `topology_updated`
  - `node_events_appended`
- 若 OpenClaw 上游只能提供部分字段，则以 Linpo 当前快照 + 增量合并为准，不把原始协议直接暴露给浏览器
- 若某类 detail 增量无法可靠恢复，必须继续显式失败，不能伪装支持

**建议步骤**：
1. 先补后端 failing tests，定义 detail 频道在 openclaw 下的最小契约
2. 实现 OpenClaw 原始消息到 `ObserverRealtimeEvent(type="topology_updated")` / `ObserverRealtimeEvent(type="node_events_appended")` 的映射
3. 验证 replay / `last_seq` / `resync_required` 在 detail 频道仍成立
4. 再补 `AgentDetail` / `NodeDetailPanel` 的前端桥接测试，确认默认 `openclaw` 路径真实闭环

**完成标准**：
- `startAgentDetailRealtime()` 在默认 `openclaw` 路径下不再只报 unsupported
- `startNodeDetailRealtime()` 可消费最小 node event append 增量
- 详情页的 topology 与节点事件测试能覆盖 `snapshot_ready`、增量更新、`resync_required`、上游 `error`

## 7. 测试与验证策略

本阶段至少覆盖以下层次：

1. **状态内核验证**：标准事件是否正确更新 state store 与 buffer
2. **HTTP 兼容验证**：v0.1 既有 3 个 GET 接口结构是否不变
3. **WebSocket 契约验证**：消息类型、频道、`seq`、恢复与 `resync_required` 是否按约定生效
4. **前端状态收敛验证**：增量消息是否正确反映到列表页与详情页
5. **失败路径验证**：OpenClaw 上游失败与 buffer 失效是否显式暴露并触发回退

若当前自动化能力不足，应优先为状态内核、WebSocket 契约与前端回退流程补齐最小测试，而不是先追求联调脚手架复杂化。

## 8. 明确不推进的实现项

以下内容即便技术上可做，也不应在 v0.2 最小实时 observer 阶段提前推进：

- 控制按钮与写操作 API
- 用户直连 OpenClaw
- 多频道聚合大盘
- 完整事件回放
- 长期历史存储
- Redis / Kafka / 持久化消息总线
- 复杂 ACK / 消费确认机制
- 资源监控、异常中心、决策追踪视图
- 聊天式事件流或完整日志控制台

## 9. 进入实现前的提醒

在真正开始编码前，执行代理需要先确认：

- 当前后端哪一层最适合承接 `ObserverStateStore` 与 `ObserverEventBuffer`
- WebSocket endpoint 放在现有 API 路由内还是单独模块更符合当前代码组织
- 前端当前列表/详情状态管理是局部 state 还是需要最小抽象层
- 哪些测试应先写失败用例，再写最小实现

若在实现中发现需要突破 observer-only、破坏现有 HTTP 契约或新增外部基础设施，应立即暂停并回到文档层处理，不得直接编码扩张。
