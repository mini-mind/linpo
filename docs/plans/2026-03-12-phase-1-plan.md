# SoulBoard 第一阶段实施计划

## 1. 目标

为 SoulBoard 的第一阶段建立一套最小但完整的产品与架构文档基础，使后续实现能够围绕“多 OpenClaw 辩论闭环”展开，而不再受旧 roboard 世界观牵引。

## 2. 第一阶段任务

### Task 1：冻结产品定义
- 明确 v0.1 的目标用户、核心闭环、非目标与成功标准
- 禁止在该阶段引入平台级能力承诺

### Task 2：冻结初始架构边界
- 明确 SoulBoard 自身要拥有的边界
- 明确 OpenClaw / OneAPI 的外部依赖定位
- 明确当前阶段不自建的能力

### Task 3：定义会话与编排语义
- 定义辩题、辩手、回合、主持人干预、总结对象
- 明确哪些对象属于产品真相源

### Task 4：定义最小产品入口
- 定义最小用户流程
- 定义最小界面结构
- 定义历史回看与总结呈现的基本要求

### Task 5：定义后续实现计划入口
- 在完成上述文档后，再拆出首轮实现计划
- 实现计划必须服从当前文档，不得倒推需求

## 3. 当前阶段完成标准
- 根目录保持干净、结构最小
- 旧项目内容已完全迁出当前仓库根目录
- 新产品方向已在文档中清晰表达
- 后续实现不再依赖旧 roboard 的文档或目录结构
