# 灵盘 v0.1 最小产品入口定义

## 1. 文档目的

本文档冻结灵盘（Linpo）v0.1 的最小用户交互流程与界面定义，作为前端实现的事实依据。

后续任何界面变更必须先更新本文档，不得以实现倒推需求。

## 2. 产品入口定位

灵盘 v0.1 的产品入口围绕**辩论创建与主持**展开，而非平台管理或实例注册。

核心用户角色：**主持人**——创建辩题、选择辩手、观看对话、插入提示、结束辩论、获取摘要。

外部 OpenClaw 注册作为高级能力存在，不占据主流程入口。

## 3. 最短用户流程

用户完成一次完整辩论的最短路径：

```
进入首页 → 填写辩题与选择辩手 → 开始辩论 → 观看对话流 
         → 发送主持人提示（可选，可多次）→ 结束辩论 → 查看摘要
```

### 3.1 流程约束

| 约束项 | 说明 |
|--------|------|
| 会话范围 | 用户在单次页面会话内完成完整闭环 |
| 持久化 | v0.1 不做辩论持久化，页面刷新后数据丢失 |
| 历史列表 | v0.1 不做历史辩论浏览，仅保留当前会话内回放 |
| 登录 | v0.1 不要求用户登录 |

### 3.2 流程分支

```
                    ┌─ 发送主持人提示 ─→ 继续观看对话
                    │
开始辩论 → 观看对话 ─┼─ 生成下一轮 ─→ 观看新发言
                    │
                    └─ 结束辩论 ─→ 查看摘要
```

## 4. 创建辩论输入项

### 4.1 必填项

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 辩题 | 多行文本 | 用户提出的讨论命题 | 「AI 结对编程应该默认开启吗？」 |
| 第一位辩手 | 下拉选择 | 从可用辩手池选择 | — |
| 第一位辩手角色名 | 单行文本 | 显示用的角色标签 | 「正方」「支持方」 |
| 第二位辩手 | 下拉选择 | 从可用辩手池选择，不可与第一位重复 | — |
| 第二位辩手角色名 | 单行文本 | 显示用的角色标签 | 「反方」「反对方」 |

### 4.2 辩手池来源标识

每个辩手选项需显示来源标签：

| 标签 | 来源 | 说明 |
|------|------|------|
| 本地 | fixture 实例 | 平台预配置的测试/演示实例 |
| 外部 | 外部注册实例 | 经审核通过的外部 OpenClaw |

### 4.3 创建前校验规则

| 场景 | 校验结果 | 提示信息 |
|------|----------|----------|
| 辩题为空 | 阻止提交 | 「请先输入辩题。」 |
| 未选择第一位辩手 | 阻止提交 | 「请选择两位辩手。」 |
| 未选择第二位辩手 | 阻止提交 | 「请选择两位辩手。」 |
| 两位辩手相同 | 阻止提交 | 「两位辩手不能重复。」 |
| 第一位角色名为空 | 阻止提交 | 「请为双方填写角色名称。」 |
| 第二位角色名为空 | 阻止提交 | 「请为双方填写角色名称。」 |
| 可用辩手不足两位 | 禁用按钮 | 「当前可用辩手不足两位，请先检查后端或本地 claw 配置。」 |

### 4.4 v0.1 不引入的输入项

- 辩论描述/背景说明
- 回合数上限设定
- 时间限制
- 自定义发言顺序
- 多于两方的辩论
- 辩手能力/模型选择

## 5. 主辩论页面布局

### 5.1 整体结构

采用左右两栏布局，响应式调整为单栏：

```
┌─────────────────────────────────────────────────────────┐
│                      顶部状态区                          │
├──────────────────┬──────────────────────────────────────┤
│                  │                                      │
│    左侧面板      │           对话流主面板                │
│   （纵向堆叠）   │         （核心交互区）                 │
│                  │                                      │
│  · 创建表单      │    状态栏                            │
│  · 主持人操作    │    操作按钮                          │
│  · 结果摘要      │    消息流                            │
│  · 外部注册入口  │                                      │
│    （折叠）      │                                      │
│                  │                                      │
└──────────────────┴──────────────────────────────────────┘
```

### 5.2 左侧面板（纵向堆叠）

| 面板 | 显示时机 | 内容 |
|------|----------|------|
| 创建辩论表单 | 辩论未创建时 | 辩题输入、辩手选择、角色名、开始按钮 |
| 主持人操作面板 | 辩论进行中/已结束时 | 主持人提示输入、结束辩论操作 |
| 结果摘要面板 | 始终显示 | 摘要字段或空状态提示 |
| 外部注册入口 | 始终显示（默认折叠） | 展开后显示注册表单 |

### 5.3 对话流面板结构

```
┌─────────────────────────────────────┐
│ 状态栏：辩题 | 回合数 | 参与者 | 状态 │
├─────────────────────────────────────┤
│ 操作按钮：[生成下一轮] [仅推进回合] [刷新记录] │
├─────────────────────────────────────┤
│                                     │
│            消息流区域               │
│         （消息气泡纵向排列）          │
│                                     │
├─────────────────────────────────────┤
│           空状态提示                │
└─────────────────────────────────────┘
```

### 5.4 消息气泡设计

#### 辩手消息

```
┌──────────────────────────────────────────┐
│ 正方 → 全体                    第 2 回合 │
├──────────────────────────────────────────┤
│ 消息正文内容...                          │
│                                          │
├──────────────────────────────────────────┤
│ 已送达                    无异常         │
└──────────────────────────────────────────┘
```

- 左上圆角较小
- 显示：发送者角色名 → 接收者（「全体」或具体角色名）
- 回合数标签（右上）
- 消息正文（支持换行预格式化）
- 投递状态行：状态文本 | 错误信息

#### 主持人消息

```
┌──────────────────────────────────────────┐
│ 主持人 → 全体                  第 1 回合 │
├──────────────────────────────────────────┤
│ 请双方各用一段话回应对方最强论点。        │
└──────────────────────────────────────────┘
```

- 背景色区分（浅蓝色调）
- 右上圆角较小
- 发送者固定显示「主持人」

### 5.5 空状态设计

| 场景 | 标题 | 说明文本 |
|------|------|----------|
| 辩论未创建 | 「先创建一场辩论」 | 「左侧填好辩题和双方角色，这里就会变成你的主持面板。」 |
| 辩论已创建但无消息 | 「对话还没开始」 | 「先点击"生成下一轮"，或先发一条主持人提示。」 |
| 摘要未生成 | 「还没有摘要」 | 「辩论结束后，这里会显示可复盘的结果概览。」 |

## 6. 主持人操作

### 6.1 发送主持人提示

| 项目 | 说明 |
|------|------|
| 输入控件 | 多行文本框，4 行高度 |
| 占位符 | 「例如：请双方各用一段话回应对方最强论点。」 |
| 触发方式 | 点击「发送提示」按钮 |
| 效果 | 生成一条主持人消息，显示在对话流中 |

**操作约束**：

| 条件 | 行为 |
|------|------|
| 辩论未创建 | 禁用输入框和按钮 |
| 辩论已结束 | 禁用输入框和按钮 |
| 内容为空 | 点击时提示「请输入主持人提示。」 |

### 6.2 主持人提示的作用

主持人提示会被记录到会话历史中，后续辩手发言时可参考此提示内容。v0.1 不强制要求辩手响应提示。

### 6.3 主持人不可直接发言

主持人不能代替辩手发言，只能通过「提示」方式影响辩论方向。

## 7. 回合推进与发言生成

### 7.1 操作按钮

| 按钮 | 说明 | 使用场景 |
|------|------|----------|
| 生成下一轮 | 触发双方轮流发言并刷新对话 | 主流操作，观看辩论进展 |
| 仅推进回合 | 仅递增回合计数，不调用辩手 | 手动控制回合数 |

### 7.2 回合语义

- 每个回合内，两位辩手各发言一次
- 主持人提示不计入回合发言数，但标记当前回合
- 回合数从 1 开始

### 7.3 操作约束

| 条件 | 行为 |
|------|------|
| 辩论未创建 | 禁用按钮 |
| 辩论已结束 | 禁用按钮 |
| 操作进行中 | 禁用按钮，显示加载状态 |

## 8. 结束辩论流程

### 8.1 结束输入

| 项目 | 说明 |
|------|------|
| 输入控件 | 单行文本框 |
| 占位符 | 「例如：核心分歧已充分展开」 |
| 默认值 | 「讨论已收束」 |
| 触发方式 | 点击「结束辩论」按钮 |

### 8.2 结束后状态变化

| 变化项 | 说明 |
|--------|------|
| 会话状态 | 变为「已结束」 |
| 按钮状态 | 禁用「生成下一轮」「仅推进回合」「结束辩论」 |
| 可用操作 | 保留「刷新记录」按钮 |
| 摘要面板 | 显示完整摘要数据 |

### 8.3 结束前校验

| 条件 | 行为 |
|------|------|
| 辩论未创建 | 提示「请先开始一场辩论。」 |
| 结束说明为空 | 提示「请填写结束说明。」 |
| 辩论已结束 | 按钮已禁用 |

## 9. 结果摘要

### 9.1 摘要字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 总消息数 | 整数 | 会话内全部消息计数（含主持人提示） |
| 总回合数 | 整数 | 最终回合数 |
| 主持人提示数 | 整数 | 主持人消息计数 |
| 结束原因 | 文本 | 用户填写的结束说明 |
| 最后发言时间 | 时间戳 | 最新一条消息的创建时间 |

### 9.2 摘要显示时机

- 辩论进行中：显示已累计的数据
- 辩论结束后：显示最终完整数据
- 辩论未创建：显示空状态提示

### 9.3 v0.1 不做的摘要能力

- 自动生成结构化总结（需 NLP 能力）
- 论点提取与对比视图
- 导出为 Markdown / PDF / JSON
- 分享链接

## 10. 历史回放

### 10.1 回放范围

仅限当前页面会话内的辩论记录。

**约束**：页面刷新后数据丢失，v0.1 不做持久化存储。

### 10.2 回放触发方式

| 触发方式 | 说明 |
|----------|------|
| 自动刷新 | 执行「生成下一轮」后自动拉取新消息 |
| 手动刷新 | 点击「刷新记录」按钮重新拉取 |

### 10.3 回放展示规则

- 按消息创建时间顺序排列（旧 → 新）
- 不支持跳转到特定回合
- 不支持消息搜索或过滤
- 不支持消息折叠/展开

### 10.4 v0.1 不做的回放能力

- 历史辩论列表页
- 按时间/辩题/参与者的搜索
- 持久化辩论记录
- 分享/导出辩论链接

## 11. 服务状态反馈

### 11.1 状态卡片

首页顶部显示服务状态卡片：

| 显示项 | 说明 |
|--------|------|
| 服务状态 | 「在线」或错误状态文本 |
| 可用辩手数 | 当前可用辩手数量 |
| 刷新按钮 | 手动刷新状态 |

### 11.2 操作加载状态

执行异步操作时：

- 顶部显示操作提示横幅（例如「正在创建辩论…」「正在生成下一轮发言…」）
- 相关按钮进入禁用状态
- 操作完成后横幅消失

### 11.3 错误处理

- 错误时显示红色横幅，包含错误信息
- 用户可继续操作或刷新页面重试
- 错误横幅在下一次操作时被替换或消失

## 12. 外部 OpenClaw 注册入口

### 12.1 入口定位

外部实例注册是**高级能力**，服务于希望接入自己的 OpenClaw 实例的高级用户。

**不作为主流程入口**，不干扰普通用户创建辩论的核心路径。

### 12.2 入口位置与展示

- 位于左侧面板底部
- 默认折叠状态，标题为「外部 OpenClaw 接入」
- 点击「展开」后显示注册表单

### 12.3 注册流程（最小化）

```
填写实例信息 → 请求 Challenge → 使用 DID 私钥签名 → 提交注册 → 等待审核
```

**必填项**：

| 字段 | 说明 |
|------|------|
| 显示名称 | 实例在辩手池中的显示名称 |
| DID | did:web 格式的身份标识 |
| Agent Card URL | Agent Card 的访问地址 |
| Inbox URL | 接收消息的 Inbox 地址 |
| Challenge 签名 | 对 Challenge 的签名证明 |

### 12.4 审核流程

注册提交后状态为「待审核」，需人工审批：

| 状态 | 说明 |
|------|------|
| pending_review | 待审核，不可用于辩论 |
| approved | 已通过，进入辩手池 |
| rejected | 已拒绝，不可用于辩论 |

### 12.5 v0.1 约束

- 仅支持 `did:web` 格式
- 仅支持人工审核
- 不支持自动批准
- 不支持完整 A2A / ANP 协议

## 13. 响应式适配

### 13.1 布局断点

| 宽度范围 | 布局 |
|----------|------|
| > 1024px | 左右双栏布局 |
| 720px - 1024px | 单栏，对话面板优先显示 |
| < 720px | 紧凑布局，所有面板纵向堆叠 |

### 13.2 移动端显示优先级

1. 对话流面板（核心交互区，优先显示）
2. 创建表单 / 主持人操作
3. 结果摘要
4. 外部注册入口（折叠）

## 14. 不在 v0.1 范围

以下能力明确推迟到后续版本：

| 类别 | 推迟项 |
|------|--------|
| 用户系统 | 登录、注册、权限、个人中心 |
| 持久化 | 辩论历史列表、历史回看、数据导出 |
| 模板 | 辩论模板、预设辩题 |
| 国际化 | 多语言支持 |
| 主题 | 深色/浅色主题切换 |
| 协作 | 邀请他人协作、分享链接 |
| 通知 | 推送通知、邮件提醒 |
| 管理 | 管理后台、用户管理、实例管理 |
| 统计 | 使用统计、分析看板 |
