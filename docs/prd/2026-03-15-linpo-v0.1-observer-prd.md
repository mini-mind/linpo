# 灵盘（Linpo）v0.1 Observer PRD

> **状态**：当前有效产品需求文档
> 
> **来源**：基于 `docs/plans/2026-03-15-linpo-v0.1-observer-design.md` 的已确认设计共识整理。

## 1. 文档目的

本文档用于冻结 Linpo v0.1 的产品需求边界，明确它是什么、服务谁、验证什么，以及当前版本明确不做什么。

本文档是当前阶段的产品事实来源；后续架构文档与实施计划必须以本文档为约束。

---

## 2. 产品定义

Linpo v0.1 是一个**面向人类的 agent 运行观测入口**。

用户登录后，可以：

- 查看自己拥有的 agents
- 进入某个 agent 的详情页
- 通过拓扑视图观察该 agent 与其 subagents 的结构关系
- 通过最小状态与事件信息理解它们当前是否活跃、最近何时活跃、经历过哪些历史事件

Linpo v0.1 的目标不是替代 agent runtime，也不是成为新的编排平台，而是先提供一个比聊天框更适合“看懂 agent 系统”的交互入口。

---

## 3. 版本定位

### 3.1 v0.0：方向验证阶段

当前仓库此前承载的辩论 demo，应视为 Linpo 的 `v0.0`：

- 用于验证多 agent 参与、过程外显、主持人视角等交互语法
- 不再作为长期产品形态定义
- 不应继续主导当前产品边界

### 3.2 v0.1：Observer 产品起点

Linpo 的真正 v0.1 从“单 agent（含 subagents）运行观测”开始。

这一版本只回答一个核心问题：

> 人类能否通过结构化界面，而不是聊天流，更容易理解一个 agent / subagent 系统？

如果这个问题成立，Linpo 才有资格继续向后扩展。

---

## 4. 产品定位与价值

Linpo v0.1 的定位不是“更强的聊天框”，而是一个新的管理入口。

它要解决的核心问题是：

- 聊天框是线性的，不适合表达层级结构
- 当 agent 派生 subagents 后，人类难以持续维持全局认知
- 对话输出适合消费结果，不适合理解系统结构
- 管理者需要额外脑力，把线性叙事重新还原成运行关系

Linpo v0.1 的产品价值在于：

- 把隐藏在聊天流中的运行结构直接外显
- 让人类先“看清楚” agent 系统
- 为后续更强的任务、决策、控制能力提供稳定入口

---

## 5. 目标用户与用户行为

### 5.1 当前阶段的用户站位

v0.1 先不限定单一垂域，也不把自己锁定为开发者工具。

当前站位是：

- 先做通用入口
- 先抽象出 agent 运行观测这一通用能力
- 后续再决定是否向特定垂域演进

### 5.2 核心用户行为

v0.1 的核心用户行为非常明确：

1. 用户登录系统
2. 查看自己拥有的 agents
3. 进入某个 agent
4. 看清该 agent 与 subagents 的结构
5. 理解哪些节点当前活跃、最近何时活跃、发生过哪些事件

因此，v0.1 的第一目标不是“操作 agent”，而是“看懂 agent”。

---

## 6. 核心页面与主对象

### 6.1 主对象

v0.1 的主对象是 **Agent**。

当前不把 task、run、session 或 workspace 作为首页主对象。它们未来可以演进为次级视图，但不是当前产品入口。

### 6.2 页面结构

v0.1 的页面结构保持最小化：

- **Agents 列表页**：查看自己有哪些 agents，并进入某个 agent
- **Agent 详情页**：通过完整拓扑视图理解单个 agent 的结构与运行状态

---

## 7. 成功标准

Linpo v0.1 的首要成功标准不是自动化、控制能力或运维深度，而是：

> 用户第一次进入后，能比聊天框更容易看懂一个 agent / subagent 系统的结构。

对应的验证问题包括：

- 用户是否能一眼分辨根 agent 与 subagents 的关系
- 用户是否能知道系统当前是否仍在运行
- 用户是否能知道某个节点最近是否活跃过
- 用户是否能通过历史事件理解节点经历过什么

---

## 8. 当前版本明确不做

为避免 v0.1 失焦，当前版本明确不做以下能力：

- 多 agent 编排
- 统一 runtime 控制
- 暂停 / 恢复 / 重试等控制操作
- 复杂任务系统
- 决策点追溯视图
- 资源监控视图
- 全局异常中心
- 用户 DIY 垂域视图
- 接入协议冻结

这些能力可以成为未来版本方向，但都不是 v0.1 的前置条件。

---

## 9. 演进边界

只有当 v0.1 证明"结构可见性"成立后，Linpo 才应继续向后扩展。

未来可能演进的方向包括：

- 任务进度视图
- 关键决策点追溯视图
- 资源监控视图
- 异常上浮与告警
- 轻量控制能力
- 用户自定义垂域视图
- 更强的多 agent 团队管理视图

但这些都不应反向影响当前 v0.1 的范围定义。

---

## 10. 版本演进规划

> **状态**：2026-03-16 重新定义的版本路线图
>
> **前提**：Linpo 作为 OpenClaw 的补充入口，核心差异化是**跨实例协作编排**（多个 OpenClaw/KimiClaw/AutoClaw 实例之间的聚合与消息传递）。

### 10.1 与 OpenClaw 的关系

| 维度 | 说明 |
|------|------|
| **底层协议** | 复用 OpenClaw Gateway WebSocket 协议，通过适配器层支持扩展 |
| **角色定位** | 补充入口，差异化在**多实例聚合 + 跨实例协作**，而非重新发明协议 |
| **多用户模型** | OpenClaw 是单用户多 agent；多用户隔离需在 Linpo 层实现 |
| **实例模型** | Linpo 聚合多个独立实例，每个用户配置自己的私有实例 |

### 10.2 版本路线图

```
v0.1 ─ Observer（当前）
│      └─ 纯观测，只读 WebSocket，验证"结构可见性"

v0.2 ─ Observer + 实时推送
│      └─ 订阅更多事件，预留 role 参数

v0.3 ─ 单 Agent 全控制
       ├─ operator role + scopes
       ├─ 设备配对流程
       ├─ 控制请求（start/pause/resume/send）
       └─ 先验证控制能力可行

v0.4 ─ 单实例控制完善
       ├─ 控制操作完整实现
       ├─ 控制状态反馈 UI（成功/失败/超时）
       ├─ 错误处理与重试机制
       └─ 单实例 Agent 管理 UI（agents.list/bindings）

v0.5 ─ 用户模型 + 实例配置基础
       ├─ 用户注册/登录（OAuth 或简单账号）
       ├─ 用户身份与 session 管理
       ├─ 实例配置入口（endpoint、名称、类型）
       ├─ 用户 ↔ 实例映射（私有实例模式）
       └─ 为多实例聚合做准备

v0.6 ─ 多实例聚合视图 ← 核心差异化
       ├─ 适配器抽象层（OpenClaw 为首个实现）
       ├─ 用户多实例统一列表（聚合 agents.list）
       ├─ 实例健康检测与状态展示
       ├─ 跨实例 Agent 拓扑视图（单视图展示多个实例的 agents）
       └─ 实例切换/筛选功能

v0.7 ─ 跨实例消息传递 ← 核心差异化
       ├─ 跨实例消息路由层
       ├─ Agent 间消息发送 UI（指定目标实例 + agent）
       ├─ 消息流可视化（展示跨实例通信）
       ├─ 消息状态追踪（发送/接收/失败）
       └─ 基础协作场景验证

v0.8 ─ 文件系统视图 + 文件传递
       ├─ 基于 read/exec 工具封装文件浏览器（Linpo 层）
       ├─ 配置编辑 UI
       ├─ 工作目录可视化
       ├─ 跨实例文件传递
       └─ 文件操作权限控制

v0.9 ─ 安全加固 + 审计
       ├─ 安全审计日志
       ├─ 操作记录追溯
       ├─ 实例连接安全验证
       └─ 漏洞修复

v1.0 ─ 内测 + 修复
       ├─ 内测用户反馈处理
       └─ 稳定性修复

v1.1 ─ 公开发布
```

### 10.3 关键设计决策

| 决策 | 说明 |
|------|------|
| **v0.4 聚焦单实例** | 控制能力完善后再引入用户模型，避免并行复杂度 |
| **v0.5 用户+实例绑定** | 用户模型与实例配置同步引入，私有实例模式简化权限 |
| **v0.6 适配器抽象** | 为 KimiClaw/AutoClaw 等预留扩展，首期只实现 OpenClaw |
| **v0.7 消息路由层** | Linpo 作为跨实例路由，不重新实现编排引擎 |
| **私有实例边界** | 用户只能在自己的实例间协作，不涉及跨用户共享 |
| **v1.0 内测缓冲** | 为公开发布预留修复空间 |

### 10.4 能力依赖表

| 能力 | OpenClaw 支持 | Linpo 需实现 |
|------|-------------|-------------|
| 单实例观测 | ✅ WebSocket + snapshot | 前端视图 |
| 单实例控制 | ✅ operator scopes | 控制界面 |
| 单实例 Agent 管理 | ✅ agents.list + bindings | 管理界面 |
| 文件系统访问 | ⚠️ 工具级（read/write/exec） | 文件浏览器封装 |
| 设备配对 | ✅ Device identity + pairing | 配对流程 |
| **多实例聚合** | ❌ 不支持 | **Linpo 核心能力** |
| **跨实例消息路由** | ❌ 不支持 | **Linpo 核心能力** |
| **适配器抽象层** | N/A | **Linpo 需实现** |
| 多用户隔离 | ❌ 不支持 | Linpo 层实现 |

### 10.5 核心差异化能力说明

**跨实例协作**是 Linpo 的核心差异化能力，指的是：

> 多个独立的 OpenClaw / KimiClaw / AutoClaw 实例之间的聚合与消息传递。

这与 OpenClaw 内部的 main agent + subagents 协作不同：

| 维度 | OpenClaw 内部协作 | Linpo 跨实例协作 |
|------|------------------|-----------------|
| 范围 | 单实例内 | 多个独立实例 |
| 身份 | OpenClaw 内部解决 | Linpo 统一 agent 身份 |
| 消息路由 | OpenClaw agentToAgent | Linpo 跨实例路由层 |
| 核心价值 | OpenClaw 已有能力 | **Linpo 核心差异化** |
