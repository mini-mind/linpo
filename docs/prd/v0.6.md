# Linpo v0.6 PRD

## 1. 产品定义

Linpo v0.6 是面向人类的多实例 agent 工作与协作入口。本阶段目标：稳定 4 页主导航 IA 与 overview 入口页，不扩张到大而全平台。

## 2. 主导航 IA 冻结

| 页面 | 路由 | 角色 |
|---|---|---|
| Topology | `/topology` | routing graph 结构视图 |
| Kanban | `/kanban` | 任务板 |
| Team | `/team` | persistent agent cards 团队入口 |
| Session | `/session/:agentId/:channelKey/:sessionKey` | 会话工作区 |

补充入口页（非主导航项）：

| 页面 | 路由 | 角色 |
|---|---|---|
| Overview | `/overview` | 默认 landing；总体态势页；桌面端通过品牌 icon、移动端通过 IA 内 icon 进入 |

## 3. 核心用户行为

1. 登录后进入 `overview` 识别总体状态。
2. 在 `topology / kanban / team` 间切换理解结构与任务。
3. 从 `team` 或明确上下文入口进入 `session`。
4. 在 `session` 中切换 channel/session 并持续协作。
5. 用户可在桌面端通过品牌 icon、移动端通过 IA 内 icon 随时回到 `overview`。

## 3.1 页面借鉴源（设计参考口径）

说明：本节用于固化页面设计与交互借鉴来源，仅作为实现参考，不改变 Linpo v0.6 的产品契约与 IA 冻结范围。

| 页面 | 主要借鉴仓库 | 借鉴范围 |
|---|---|---|
| Overview（`/overview`） | `openclaw-control-center`、`openclaw-mission-control` | 总览态势信息分层、运营态可读性表达 |
| Topology（`/topology`） | `openclaw-gateway-routing-graph` | 网关链路可视化、拓扑/事件联动表达 |
| Kanban（`/kanban`） | `openclaw-mission-control`、`openclaw-manager` | 任务编排板结构、流程化操作路径 |
| Team（`/team`） | `openclaw-control-center`、`openclaw-mission-control` | Staff/Agent 运营视角、团队状态与协作入口 |
| 跨页契约与接口 | `openclaw` | Gateway/WebSocket 能力与协议对齐基线 |

参考仓库路径（本地）：`/data/projects/openclaw`、`/data/projects/openclaw-control-center`、`/data/projects/openclaw-gateway-routing-graph`、`/data/projects/openclaw-manager`、`/data/projects/openclaw-mission-control`。

## 4. 路由与契约硬约束

- `/overview` 是默认 landing。
- 主导航不展示 `overview` 文本项。
- 桌面端通过品牌 icon 跳转 `/overview`。
- 移动端通过 IA 内 icon 跳转 `/overview`，不使用顶部品牌栏占位。
- 移动端用户信息入口收敛到 IA 最后一项（账户菜单），不使用页面悬浮入口。
- `session` canonical 路由：`/session/:agentId/:channelKey/:sessionKey`。
- 空工作区：`/session/:agentId/__none__/__new__`。
- 空会话：`/session/:agentId/:channelKey/__new__`。
- `__none__` 与 `__new__` 为保留字。
- 若外部 `channelKey/sessionKey` 与保留字冲突，进入系统前必须做稳定转义：`x--<original>`。
- 仅当值以前缀 `x--` 开头且去前缀后命中保留字时才执行反转义。
- 五页必须承接：`request_id`、`freshness`、`partial_failure`、`diagnostics`。
- `freshness` 词汇固定：`fresh / stale / failed`。
- 会话消息支持 Markdown。
- 工具调用消息展示为摘要，不暴露 raw JSON。

## 5. 执行范围

**In-Scope**

- 4 页主导航 IA 与 overview 入口页的行为收敛与缺陷修复
- 路由与共享契约一致性维护
- 测试、部署、浏览器验收闭环（详细流程见 `docs/resources/test-resources.md`）

**Out-of-Scope**

- `settings`
- `profile`
- 第五个主导航页面
- 与当前 IA 无关的平台扩张

## 6. 成功标准

- 用户首次进入可快速理解系统态势与结构。
- 用户可沿“态势（overview）-> 结构 -> 任务 -> 团队 -> 会话”路径推进，并可通过品牌 icon 回到 overview。
- 各页在成功、部分成功、失败、未授权场景都有明确诊断反馈。

若产品边界或成功标准与 `docs/architecture/v0.6.md` 或 `docs/resources/test-resources.md` 发生冲突，以 `docs/prd/v0.6.md` 为准。
