# Linpo v0.6 PRD

## 1. 产品定义

Linpo v0.6 是面向人类的多实例 agent 工作与协作入口。本阶段目标：稳定 5 页 IA 主路径，不扩张到大而全平台。

## 2. IA 冻结

| 页面 | 路由 | 角色 |
|---|---|---|
| Overview | `/overview` | 默认入口；总体态势 |
| Topology | `/topology` | routing graph 结构视图 |
| Kanban | `/kanban` | 任务板 |
| Team | `/team` | persistent agent cards 团队入口 |
| Session | `/session/:agentId/:channelKey/:sessionKey` | 会话工作区 |

## 3. 核心用户行为

1. 登录后进入 `overview` 识别总体状态。
2. 在 `topology / kanban / team` 间切换理解结构与任务。
3. 从 `team` 或明确上下文入口进入 `session`。
4. 在 `session` 中切换 channel/session 并持续协作。

## 4. 路由与契约硬约束

- `/overview` 是默认 landing。
- `session` canonical 路由：`/session/:agentId/:channelKey/:sessionKey`。
- 空工作区：`/session/:agentId/__none__/__new__`。
- 空会话：`/session/:agentId/:channelKey/__new__`。
- `__none__` 与 `__new__` 为保留字。
- 若外部 `channelKey/sessionKey` 与保留字冲突，进入系统前必须做稳定转义：`x--<original>`。
- 仅当值以前缀 `x--` 开头且去前缀后命中保留字时才执行反转义。
- 五页必须承接：`request_id`、`freshness`、`partial_failure`、`diagnostics`。
- `freshness` 词汇固定：`fresh / stale / failed`。
- 会话消息支持 Markdown。
- 工具调用消息展示为摘要，不暴露 raw JSON。

## 5. 执行范围

**In-Scope**

- 5 页 IA 的行为收敛与缺陷修复
- 路由与共享契约一致性维护
- 测试、部署、浏览器验收闭环（详细流程见 `docs/resources/test-resources.md`）

**Out-of-Scope**

- `settings`
- `profile`
- 第六个有效主页面
- 与当前 IA 无关的平台扩张

## 6. 成功标准

- 用户首次进入可快速理解系统态势与结构。
- 用户可沿 5 页 IA 完成“态势 -> 结构 -> 任务 -> 团队 -> 会话”路径。
- 各页在成功、部分成功、失败、未授权场景都有明确诊断反馈。

若产品边界或成功标准与 `docs/architecture/v0.6.md` 或 `docs/resources/test-resources.md` 发生冲突，以 `docs/prd/v0.6.md` 为准。
