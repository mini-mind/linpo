产品需求文档：灵板（RoBoard）

文档版本 v3.0
更新日期 2026-02-26
状态 正式版

1. 产品概述

1.1 产品名称

· 英文名：RoBoard（Robot + Board，机器人控制面板）
· 中文名：灵板（灵动指挥，智能面板）

1.2 一句话定义

灵板是一个“可指挥的多智能体团队”平台：用户用自然语言下达目标，系统组建团队、实时可视化进度，用户可随时干预，并能通过安装或自建技能扩展能力边界。

1.3 产品定位

灵板不是单点聊天工具，而是 AI 团队的操作系统。它面向非技术业务操盘手提供可视化、可干预、可复用的团队指挥能力。

1.4 核心价值

· 零门槛组建团队：一句话描述需求，系统自动搭建多智能体协作结构。
· 过程透明：状态与步骤可视化，关键节点可回溯。
· 随时干预：执行中可暂停/重试/改规则，保持掌控权。
· 生态兼容：可直接安装社区技能，避免重复造轮子。
· 自我进化：智能体可生成新技能并自用，能力持续扩展。
· 知识沉淀：团队结构与偏好可复用、可共享。
· 预制能力：可从模板库快速选用预配置的专家 Agent（如搜索专家、分析专家）。

2. 目标用户与场景

2.1 核心用户画像

· 业务操盘手：采购、生产、运营等岗位，面对多任务线但缺乏技术资源。
· 解决方案构建者：AI 产品经理/行业专家，为内部或客户搭建垂直应用。
· 技术极客（可选）：使用进阶功能进行深度定制与调试。

2.2 典型场景

· 供应商监控：库存/价格阈值预警，日汇总。
· 工厂早会助手：采集数据、分析偏差、生成提纲。
· 竞品追踪：定时抓取网站，分析价格变化。
· 舆情监控：关键词趋势、异常预警。
· 文档自动化：从纪要生成文档与验收清单。

3. 产品核心功能（MVP范围）

3.1 自然语言创建智能体团队

· 用户以日常语言描述目标。
· 系统解析并生成团队树预览（角色、职责、依赖关系）。
· 用户确认后创建并执行，过程无需触碰技术细节。

3.2 树状可视化与实时状态监控

· 指挥舱显示团队树，节点颜色表示状态（运行/成功/失败/等待）。
· 点击节点查看步骤、进度、摘要与工具结果。
· 状态更新通过 WebSocket 实时推送。

3.3 自然语言干预

· 底部输入框支持自然语言控制：修改规则、暂停、重试。
· 系统解析指令并实时作用于目标智能体。
· 支持单体控制按钮（暂停/继续/重试）。

3.4 可信来源机制

· 每个智能体可绑定一组文档目录作为信息来源。
· 输出必须基于来源文档，禁止幻觉。
· 支持 txt、pdf、markdown、图片（OCR 依赖模型）。

3.5 Skill 自举（核心差异化）

· 当现有技能不足时，智能体可生成新技能代码并安装使用。
· 生成流程由系统完成，用户只需知情。
· 自举核心为元技能（skill-creator），由其根据需求生成新技能。
· 新技能运行在沙箱环境，隔离敏感资源。

3.6 兼容社区技能市场

· 提供“安装技能”能力，支持从社区仓库检索与安装。
· 可通过自然语言指令触发安装。
· 初期仅允许已验证技能。
· 技能调用由执行器自动完成，不依赖用户手动点击触发。

3.7 Agent 模板库

· 提供预制 Agent 模板（如搜索专家、分析专家、文档撰写专家）。
· 支持从模板实例化 Agent，自动绑定技能与可信来源。
· 团队架构可导出为 YAML/JSON，导入后可一键复用团队能力。
· 预制 Agent 可直接对接内部服务（如 searcher 接入 searxng）。
3.8 多端协同基础

· 指挥舱支持响应式布局，移动端可查看关键状态。
· 移动端支持轻量干预，复杂操作引导至 PC。
· 登录后多端同步任务进度。

3.9 文件系统即界面（进阶）

· 技术用户可浏览智能体工作目录并预览产物。
· 支持文本/图片/PDF 预览。

4. 技术架构要点

4.1 Agent 核心模型

每个 Agent 通过“文件系统 + 事件驱动循环 + 工具调用”实现自治。示例结构：

```
/agents/<agent_id>/
├── identity.json        # 元数据：ID、名称、父ID、角色、状态、session_key
├── mission.md           # 当前任务描述
├── plan.md              # 子任务列表（JSON）
├── context/
│   ├── sources/         # 可信来源（只读）
│   └── workspace/       # 中间产物
├── children/            # 子 Agent 目录（系统维护）
├── skills/              # 自建 Skill（Python 文件）
├── memory/
│   └── preferences.md   # 用户偏好（仅顶层）
└── logs/                # 执行日志
```

4.2 事件驱动执行

· 监听 mission、子 Agent 完成与定时事件。
· 每轮执行包含拆解、派发、汇总，再进入休眠。
· 干预可通过更新 mission 触发。

4.3 Skill 自举机制

· 通过内置工具生成新技能代码并写入 skills/。
· 生成需遵循模板与安全约束（由 skill-creator 负责）。
· 生成后的技能以事件形式记录与回放。

4.4 社区技能集成

· 提供安装工具从社区拉取技能并落盘。
· 初期需要依赖与安全校验。
· 技能分为三层：内置技能（执行器封装）> 租户私有技能（租户 FS）> 平台预制技能（共享维护）。
· 执行器在 Docker 沙箱中运行技能，带生命周期管理与资源限制。

4.5 多端同步

· 后端通过 WebSocket 推送状态，前端缓存更新。
· 移动端与 Web 端共享同一 API。

5. MVP 范围与优先级

P0（必须，4 周内）

· 自然语言创建团队（基础版）
· 树状可视化 + WebSocket 实时状态
· 自然语言干预（基础）
· 可信来源机制
· Agent 基础执行引擎（FS + 事件驱动）
· 前端基础界面（指挥舱）

P1（争取，4-6 周）

· Skill 自举（初版）
· 社区技能集成（搜索/安装/调用）
· Agent 模板库（预制 Agent + 团队导出/导入）
· 多端协同（移动端基础查看）

· Skill 自举（初版）
· 社区技能集成（搜索/安装/调用）
· 团队架构导出/导入（YAML）
· 多端协同（移动端基础查看）

P2（后续迭代）

· 记忆版本管理
· 社区模板市场
· 多用户协作
· 高级安全沙箱（容器化）

6. 关键术语解释

· 智能体（Agent）：独立运行的 AI 单元，拥有文件系统与执行循环。
· Skill：智能体可调用的工具函数，来源可为内置/社区/自建。
· SOP：产品语境下指 TODO/计划列表，来源为 `plan.md`，前端展示为 `plan_subtasks`。当前实现仍保留 SOP 模板（`sops/templates/*.md` + `mission.md` + `/api/agents/{agent_id}/sop`），与计划列表并存。
· Session Key：Agent 标识与权限依据。
· 可信来源：Agent 执行时必须遵守的文档目录。

7. 成功指标（内部使用）

· 用户任务成功率：首次使用 5 分钟内完成简单场景的比例。
· 干预准确率：自然语言干预被正确理解并执行的比例。
· Skill 安装/自建成功率：新增能力获取成功的比例。
· 用户留存：次日留存、周留存等核心指标。
