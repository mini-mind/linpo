# Linpo v0.6 Architecture

> 前置：`docs/prd/v0.6.md`

## 1. 架构目标

在不扩展产品边界的前提下，稳定支撑 5 页 IA：`overview / topology / kanban / team / session`。

## 2. 页面职责与 Guardrails

| 页面 | 主职责 | Guardrail |
|---|---|---|
| Overview | 总体态势入口 | 不回退为 watchlist 或旧 observer 首页 |
| Topology | 四泳道 routing graph | 不回退为 graph-only，不以侧栏挤占主舞台 |
| Kanban | 任务板 | 不回退为只读信号板 |
| Team | persistent agent cards 团队入口 | 不可附录化、可选化 |
| Session | 会话工作区 | 不回退为旧 drill-down 单列页 |

## 3. 契约冻结

五页共享字段：

- `request_id`
- `freshness`
- `partial_failure`
- `diagnostics`

`freshness` 词汇冻结：`fresh / stale / failed`。

session 路由冻结：

- `/session/:agentId/:channelKey/:sessionKey`
- `/session/:agentId/__none__/__new__`
- `/session/:agentId/:channelKey/__new__`
- `__none__` / `__new__` 为保留字；冲突值采用 `x--<original>` 稳定转义，并按保留字命中规则反转义。

## 4. 最小状态与事件模型

### 最小状态字段

- `name`
- `status`
- `is_active`
- `child_count`
- `last_active_started_at`
- `event_history`

### 最小事件集合

- 结构/状态：`agent_created`、`subagent_created`、`activity_started`、`activity_stopped`、`status_changed`、`node_finished`
- 任务边界：`task_started`、`task_finished`、`task_interrupted`

## 5. 后端分层冻结

唯一调用链：

`API -> Application -> Domain Contract -> Provider Adapter -> Infra/Persistence`

分层职责：

- API：路由、鉴权、校验、响应封装
- Application：用例编排
- Domain Contract：系统 canonical 契约
- Provider Adapter：外部协议差异吸收
- Infra：客户端、重试、超时、限流、配置
- Persistence：配置、映射、会话、审计留痕

## 6. Breakly 迁移纪律

- 一次性切换，不保留长期双轨兼容。
- 旧路径、过渡分支、死代码必须清理。
- 不保留无主 TODO 与不可达调用链。

## 7. 收口与验证

- 每个 major feature 完成后应确认实现与 PRD、Architecture 及测试资源文档一致。
- 架构层面的验证依赖 `docs/resources/test-resources.md` 中定义的环境、命令与验收门禁。

若架构边界与 `docs/prd/v0.6.md` 或 `docs/resources/test-resources.md` 发生冲突，以 `docs/architecture/v0.6.md` 为准。
