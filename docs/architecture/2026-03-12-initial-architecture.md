# 灵盘初始架构

## 1. 架构目标

灵盘（Linpo）当前不是一个通用多智能体平台，也不是旧 roboard 的延续实现。

当前初始架构的目标只有一个：

> 以最小必要系统边界支撑“多 OpenClaw 辩论闭环”成立，并为后续阶段扩张保留清晰演进空间。

## 2. 初始系统边界

### 2.1 灵盘当前需要拥有的边界
- 产品入口与用户交互层
- 辩论会话模型与状态真相源
- 辩手编排逻辑
- 结构化总结产出
- 最小必要的事件/历史回放能力

### 2.2 灵盘当前不需要自建的边界
- 自研运行时内核
- 自研 llm relay
- 自研搜索链路
- Browser automation 执行层

## 3. 外部依赖定位

### 3.1 OpenClaw
OpenClaw 在当前阶段被视为外部运行时内核。

它负责承接辩手执行、会话运行与模型调用相关的运行时能力，但不等于灵盘的完整产品控制面。

### 3.2 OneAPI
OneAPI 在当前阶段被视为外部 LLM relay。

灵盘可在其上保留极薄的适配层，以维持自身需要的模型引用与错误语义边界。

## 4. 当前最小架构原则
- 先定义产品闭环，再决定代码目录
- 先保持边界最少，再考虑拆分
- 先接受外部系统承担通用能力，再决定哪些能力值得内建
- 任何新增模块都必须服务当前阶段目标

## 5. 当前架构约束
- 不预设旧 roboard 的 workspace-first 模型
- 不预设旧 roboard 的 runtime/tool/browser/search 边界
- 不提前冻结后期平台化能力
- 不把“未来也许要做”当成当前必须实现

## 6. 下一步架构任务
当前初始架构之后，下一步应继续细化：
- 辩论会话对象模型
- 辩手角色与回合语义
- OpenClaw 接入边界
- OneAPI 适配边界
- 历史记录与总结输出结构
