# Claw 会话型接入与点对点消息中转最小架构

## 1. 目标

本文档定义灵盘（Linpo）在当前 MVP 起点下的最小架构补充：

> 允许外部 Claw 以会话型方式接入灵盘，并通过灵盘完成点对点消息中转与历史回放。

该架构用于支撑更大闭环之前的最小基础能力验证。当前重点不是直接实现完整辩论编排，而是先验证：

- 外部 Claw 可以被灵盘挂入一次会话
- 会话中的 Claw 之间可以通过灵盘发生受控交互
- 交互过程可以被灵盘记录和回放

## 2. 非目标

当前文档明确不冻结以下能力：

- 长期注册型 Claw 池
- Claw 自主发现与平台自动纳管
- 多方广播 / 群聊模型
- 辩论回合状态机
- 主持人干预语义
- 结构化总结生成
- 多租户与鉴权模型
- 将测试用 Claw 视为平台运行单元

## 3. 系统边界

### 3.1 灵盘当前需要拥有的边界

- 会话创建与关闭
- 会话级 Claw 挂载关系
- 点对点消息中转
- 最小消息历史记录
- 历史回放读取

### 3.2 灵盘当前不拥有的边界

- 外部 Claw 的运行时生命周期
- 外部 Claw 的模型调用与工具执行
- 外部 Claw 之间的直连通信
- 长期在线状态管理

### 3.3 外部 Claw 的定位

外部 Claw 是灵盘的接入对象，而不是灵盘的内置组件。

当前 TDD 环境下启动的 3 个 OpenClaw 容器，仅用于模拟未来用户自己的 Claw：

- 它们是测试夹具（test fixtures）
- 它们不属于灵盘产品运行单元
- 它们不应在产品架构图中被建模为平台自带角色或固定节点

## 4. 最小对象模型

### 4.1 ClawEndpoint

表示测试环境中可被挂入会话的外部 Claw 端点配置。

最小字段：
- `id`
- `name`
- `endpoint_ref`
- `enabled`

说明：
- 当前阶段仅要求支持“平台预配置端点”
- `ClawEndpoint` 不是长期注册实体，只是当前测试/接入环境下的可引用配置

### 4.2 Session

表示一次临时交互会话。

最小字段：
- `id`
- `status`（`created` / `active` / `closed`）
- `attached_claw_ids`
- `created_at`
- `closed_at`（可空）

说明：
- Session 是消息中转与回放的作用域
- 第一版不要求表达辩论轮次、主持人状态或总结状态

### 4.3 Message

表示一条经灵盘中转的点对点消息记录。

最小字段：
- `id`
- `session_id`
- `from_claw_id`
- `to_claw_id`
- `content`
- `created_at`

说明：
- 第一版不加入额外投递状态
- 第一版不加入请求-响应关联
- 第一版不加入广播目标集合

### 4.4 ReplayRecord

表示可回放历史的最小读取视图。

最小要求：
- 能按时间顺序返回某个 Session 下的全部 Message
- 回放来源以灵盘内部记录为准

## 5. 最小交互流程

### 5.1 预配置测试端点

在测试环境中，灵盘预先知道若干外部 Claw 端点配置。

这些端点：
- 由测试环境提供
- 用于会话创建时引用
- 不等于产品级长期注册池

### 5.2 创建会话

用户或测试驱动创建一个新的 Session。

结果：
- 获得新的 `session_id`
- Session 初始状态为 `created`

### 5.3 挂载外部 Claw

创建 Session 后，将一个或多个预配置 `ClawEndpoint` 挂入该 Session。

结果：
- Session 建立 `attached_claw_ids`
- 当至少两个 Claw 挂载完成后，可进入最小点对点交互

### 5.4 点对点消息中转

一次最小交互为：

- Claw A 向 Linpo 提交面向 Claw B 的消息
- Linpo 校验该消息属于某个有效 Session，且收发双方都已挂载
- Linpo 将消息记入内部历史
- Linpo 将该消息中转给目标 Claw

约束：
- 所有 Claw-to-Claw 交互必须经过 Linpo
- 第一版不支持直接 Claw-to-Claw 通道
- 第一版不支持默认广播给所有 Claw

### 5.5 历史回放

任一 Session 的历史回放由灵盘提供。

回放最小要求：
- 可读取某个 Session 的全部消息
- 消息按写入顺序或时间顺序呈现
- 回放内容以灵盘内部记录为准，而不依赖外部 Claw 自报

## 6. 真相源规则

### 6.1 会话真相源

Session 的存在性、状态和挂载关系，以灵盘为唯一真相源。

### 6.2 消息真相源

Message 是否存在、属于哪个 Session、由谁发给谁，以灵盘内部记录为唯一真相源。

### 6.3 回放真相源

历史回放由灵盘生成，不从外部 Claw 聚合历史。

## 7. 测试夹具定位

### 7.1 当前 3 个 OpenClaw 容器的角色

当前 TDD 环境中的 3 个 OpenClaw 容器：

- 用于模拟外部用户自己的 Claw
- 用于验证灵盘的会话挂载与消息中转能力
- 仅属于测试与开发验证环境

### 7.2 不应出现的误建模

以下建模在当前阶段都不成立：

- 把这 3 个 Claw 写成灵盘的内置辩手
- 把这 3 个 Claw 写成灵盘默认运行拓扑的一部分
- 把测试夹具容器写成平台长期依赖节点

### 7.3 测试环境口径

测试环境可以存在：

- `linpo` 服务
- 3 个 OpenClaw fixture 容器
- 用于联调与集成测试的最小脚本/配置

但这属于测试与验证拓扑，不等于产品部署拓扑。

## 8. 与后续阶段的关系

当前架构补充定义的是更大闭环之前的最小接入与中转基础。

后续可以在此之上继续演进：

- 从会话型接入扩展到长期注册型接入
- 从点对点中转扩展到多方交互
- 在中转基础上叠加辩论回合语义
- 在历史记录基础上叠加结构化总结产出

但这些都不属于本文档当前冻结范围。

## 9. 当前阶段落盘要求

基于本文档，后续实施计划必须遵守以下约束：

- 先以文档为准，不倒推需求
- 先验证会话挂载 + 点对点中转 + 回放成立
- 不提前实现长期注册、广播、复杂编排
- 不把测试夹具误写成产品组件
