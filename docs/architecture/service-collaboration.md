## 网络边界

### 公网暴露
- `ravin:80` - HTTP (重定向到 HTTPS)
- `ravin:443` - HTTPS (主入口)
- `local:8000` - API (开发调试)
- `local:7200` - Playwright Gateway (仅 HK 访问)

### 内网通信
- `ravin:8081` - SearXNG (仅本机 + mcp-server)
- `ravin:8082` - Gateway (仅本机)
- `local:5432` - PostgreSQL (仅本机)
- `local:6379` - Redis (仅本机)

### 外部服务
- LLM Providers (OpenAI, Claude 等)
- Search Engines (Google, Bing, DuckDuckGo 等)
- SMTP (邮件发送)

## 关键设计决策

### 1. 为什么拆分部署？

- **网络优势**: ravin 在美国，可直接访问所有国际服务
- **资源优化**: 本地只运行后端重服务，frontend 集中在 ravin
- **安全性**: 数据库等敏感服务不暴露在公网

### 2. 为什么 searxng 在 ravin？

- **GFW 绕过**: ravin 可直接访问 google、duckduckgo 等
- **搜索结果质量**: 启用所有 20+ 引擎，无阻断
- **集中管理**: 单一 searxng 实例服务所有后端

### 3. 为什么 api 暴露双端口？

- `127.0.0.1:8005` - 本地开发调试
- `0.0.0.0:8000` - ravin 的 web-frontend 调用

### 4. 为什么用 Redis Streams？

- **解耦**: api 和 worker 不直接通信
- **可靠性**: 任务持久化，不丢失
- **扩展性**: 可水平扩展多个 worker

## 故障排查路径

### 前端无法访问
```
1. 检查 ravin edge 状态
2. 检查 gateway 配置
3. 检查 SSL 证书
4. 检查防火墙规则
```

### API 调用失败
```
1. 检查 api 健康：curl http://127.0.0.1:8005/health
2. 检查 postgres 连接
3. 检查 redis 连接
4. 检查日志：docker logs roboard-api-1
```

### 搜索无结果
```
1. SSH 登录 ravin
2. 测试 searxng: curl http://127.0.0.1:8081/search?q=test&format=json
3. 检查引擎状态
4. 检查 mcp-server SEARXNG_URL 配置
```

### 任务不执行
```
1. 检查 dispatch 状态
2. 检查 Redis Streams: redis-cli MONITOR
3. 检查 worker-playwright 日志
4. 检查 Docker socket 代理
```
