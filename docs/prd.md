# Linpo PRD

## 1. 产品定义

Linpo 是位于 OpenClaw 与用户之间的人机协作编排交互层，不是 OpenClaw 的替代后端。
OpenClaw 提供 Agent 执行能力，Linpo 负责流程可视化、任务编排、审批与协作体验。

## 2. v0.7 目标

v0.7 目标是打通以下闭环：

`一句话需求 -> 流程图（可编辑）-> DAG 任务队列 -> 看板并行推进 -> 统一审批 -> 结果预览与调试`

产品主界面收敛为看板页面和顶部工具栏，不再维持多页 IA。

## 3. 界面与路由约束

### 3.1 路由

- 默认登录后进入 `/kanban`。
- v0.7 保留：`/login`、`/landing`、`/kanban`、`/flow`。
- 历史页面路由（`overview/topology/team/session`）不再作为主产品入口。

### 3.2 页面结构

- 落地页：`/landing`，用于价值说明与主入口引导。
- 主体：看板（默认按状态分列，可切换按 agent 分列；列宽固定并支持横向滚动查看）。
- 按 agent 分列时提供“新增 Agent”入口列，支持弹窗创建新的主 Agent 列。
- 顶部工具栏：新建任务、流程图入口、事件侧栏入口、审批入口、刷新/筛选。
- 品牌区（`LP/灵盘`）支持点击跳转到落地页。
- 工具面板：流程调试输入框、文件预览面板。

## 4. 核心用户行为

1. 用户在看板点击“新任务”，输入一句话业务需求。
2. 系统调用 OpenClaw 能力生成初始流程图。
3. 用户可手动编辑流程图节点与依赖关系。
4. 系统将流程图解析为可并行子任务并写入看板队列。
5. 调度阶段遇到敏感操作，统一进入审批队列，用户一次审批。
6. 每个任务卡片可查看执行日志、消息产出与文件预览。
7. 用户在调试输入框补充上下文或修正指令，触发任务再执行。

## 5. 功能范围

**In-Scope（v0.7）**

- 句子到流程图生成（调用 OpenClaw）
- 流程图手动编辑
- DAG 依赖解析与并行子任务入板
- 看板视图切换（状态/agent）
- 敏感操作统一审批
- 任务卡片结果查看与文件预览
- 事件侧边栏
- 卡片字段可扩展数据结构（支持异构字段）
- 默认以 `claw1` 作为联调后端
- 支持 Tauri 构建

**Out-of-Scope（v0.7）**

- 模板市场（Marketplace）
- agent 消耗统计
- agent 拓扑配置页

以上能力延后到 v0.8。

## 6. 关键实体

- `Flow`：流程定义，包含节点、边、版本与来源提示词。
- `Task`：流程解析后的可调度单元，含依赖、状态、执行目标与产出索引。
- `Approval`：敏感动作审批请求与决议。
- `Artifact`：任务产出（文本、结构化数据、文件引用、预览元数据）。
- `DebugInput`：用户追加输入与重试意图。

## 7. 成功标准

- 用户可在单页面内完成“描述需求 -> 生成流程 -> 并行执行 -> 审批 -> 查看产出”。
- 流程编辑后的依赖关系可稳定转译为任务队列，无错乱执行顺序。
- 敏感操作不会绕过审批入口。
- 任务卡片可稳定展示文本与文件预览结果。
- 前端可以通过 Tauri 构建产出桌面应用。

若产品边界或成功标准与 `docs/architecture.md` 或 `docs/test-resources.md` 冲突，以 `docs/prd.md` 为准。
