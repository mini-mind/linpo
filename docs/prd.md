# Linpo PRD

## 1. 产品定义

Linpo 是位于 OpenClaw 与用户之间的人机协作编排交互层，不是 OpenClaw 的替代后端。
OpenClaw 提供 Agent 执行能力，Linpo 负责流程可视化、任务编排、审批与协作体验。

## 2. v0.7 目标

v0.7 目标是打通以下闭环：

`一句话需求 -> 流程图（可编辑）-> DAG 任务队列 -> 看板并行推进 -> 统一审批 -> 结果预览与调试`

产品主界面收敛为看板页面和顶部工具栏，不再维持多页 IA。

## 3. 界面与路由约束

### 3.1 路由

- 默认登录后进入 `/kanban`。
- v0.7 保留：`/login`、`/landing`、`/kanban`、`/flow`、`/flow/edit/:flow_id`。
- `/landing` 面向游客可直接访问，不要求登录。
- 历史页面路由（`overview/topology/team/session`）不再作为主产品入口。

### 3.2 页面结构

- 落地页：`/landing`，用于价值说明与主入口引导；视觉上突出核心优势，并预留 Image 占位区用于后续产品截图与宣传素材。
- 主体：看板（默认按状态分列，可切换按 agent/需求分列；列宽固定并支持横向滚动查看）。
- 按 agent 分列时提供“新增 Agent”入口列，支持弹窗创建新的主 Agent 列。
- 支持删除单个需求节点与整组需求节点。
- 顶部工具栏：`➕任务` 与分列方式（保留需求数量统计）。
- 点击 `➕任务` 打开弹窗，包含需求输入与 Agent 指派；弹窗提供“创建任务/创建流程”双入口。
- 顶部导航提供并列入口：`看板` 与 `流程`，其中 `流程` 跳转到“所有流程”页面（`/flow`）。
- `看板` / `所有流程` / `编辑流程` 三个主工作页统一使用贴顶的扁平工具栏视觉风格。
- “所有流程”页面展示流程列表，作为“我的流程”目录入口；点击某个流程进入 `编辑流程` 页面（`/flow/edit/:flow_id`）。
- “所有流程”页面不保留顶部额外 title/描述，统一使用扁平工具栏承载交互。
- “所有流程”工具栏左侧提供流程筛选/排序能力，右侧放置“新建流程”按钮。
- “所有流程”卡片恢复多列网格布局（自适应列宽）。
- 流程卡片需提供“编辑”入口，支持：`重命名流程`、`删除流程`。
- 点击流程卡片主体可直接进入 `编辑流程` 页面。
- 点击“所有流程”页面工具栏的“新建流程”按钮，先弹窗填写流程名/需求（均可为空）；流程拆解固定使用 `claw3`（后续通过配置改写）。
- 若需求为空：直接创建空流程并进入编辑页；若填写了需求：弹出“生成中”提示，后端完成拆解后自动跳转编辑页并载入流程草图。
- `编辑流程` 页面采用“顶部独立工具栏 + 画布主区域”结构，画布占据其余空间并可滚动查看。
- `编辑流程` 页工具栏左侧为目录结构：`我的流程 / {当前流程名}`；点击 `我的流程` 返回 `/flow`，点击 `{当前流程名}` 打开流程详情卡片并支持重命名。
- 初次创建流程时，默认流程名为首次发送需求的前 8 个字符加 `...`（超长截断）。
- `编辑流程` 页工具栏右侧为按钮组：`运行`（未入看板）/`停止流程`（已入看板且冻结）。
- 已提交到看板的流程默认冻结不可编辑；点击 `停止流程` 后停止后续节点调度，并恢复为可编辑、可再次运行流程状态。
- 流程画布采用横向多泳道布局：每个泳道占用一列，顶部冻结一行显示泳道标题。
- 流程画布支持人工编辑：节点/连线均可增删改；节点上下左右各有一个连接点用于连线；双击画布弹窗创建节点，双击节点弹窗编辑节点。
- 节点编辑需支持“标题 + 详细描述”，描述用于后续任务执行上下文。
- 双击顶部空白区可创建泳道（可指定泳道名称与委派 Agent），双击泳道标题可修改泳道名称与委派 Agent。
- 节点创建在双击位置并归属所在泳道；泳道宽度根据内部节点占用自适应扩展，右侧泳道顺延。
- 节点拖拽支持跨泳道移动，跨列后自动切换节点归属泳道与执行 Agent。
- 连线交互采用“从连接点拖拽到连接点”；渲染时根据节点相对位置自动选择最短接入点组合，而非节点中心连线。
- 不再暴露 L1~Lx 层级编辑；任务拓扑层级由系统在提交前按 DAG 拓扑动态计算，并据此分配到可执行 Agent。
- 节点间数据流通统一约束为“临时文件通道”。
- 品牌区（`LP/灵盘`）支持点击跳转到落地页。
- 流程页不再保留底部输入框/消息流面板，流程新增与拆解入口统一上收至“所有流程”页新建流程弹窗。

## 4. 核心用户行为

1. 用户在看板点击 `➕任务`，输入一句话需求并指派 Agent。
2. 若点击“创建任务”，系统直接写入 `queued` 队列并触发调度。
3. 用户进入“所有流程”页点击“新建流程”，可选填写流程名与需求；流程拆解固定使用 `claw3`。
4. 若需求为空则直接创建空流程；若填写需求则后端拆解并生成流程草图后自动跳转编辑页。
5. 用户可在编辑页双击画布创建节点、双击节点编辑节点、拖线连接节点、编辑泳道标题与委派 Agent。
6. 用户点击“运行”，系统按当前节点/连接关系做 DAG 拓扑计算后写入看板 `queued` 队列。
6. 调度器从 `queued` 队列取一个可执行任务分配给 agent；任务执行完成后再取下一个。
7. agent 通过 `task-run events` 回调上报 `started/progress/completed/failed/need_approval`，后端按事件推进状态机。
8. 调度阶段遇到敏感操作，统一进入审批队列，用户一次审批。
9. 每个任务卡片可查看执行日志、消息产出与文件预览。
10. 节点间数据交换通过临时文件传递，避免上下游节点共享内存上下文。
11. 用户可在流程页人工新增/删除节点、修改节点属性、创建/删除连接，再运行流程到看板。
12. 已运行流程默认冻结；用户可点击“停止流程”阻断后续调度，并回到可编辑状态重新运行流程。

## 5. 功能范围

**In-Scope（v0.7）**

- 句子到流程图生成（调用 OpenClaw）
- 流程图手动编辑
- DAG 依赖解析与并行子任务入板
- 看板视图切换（状态/agent/需求）
- 需求节点删除（单节点/整组）
- 敏感操作统一审批
- 任务卡片结果查看与文件预览
- 事件侧边栏
- 卡片字段可扩展数据结构（支持异构字段）
- 默认以 `claw1` 作为联调后端
- 支持 Tauri 构建

**Out-of-Scope（v0.7）**

- 模板市场（Marketplace）
- agent 消耗统计
- agent 拓扑配置页

以上能力延后到 v0.8。

## 6. 关键实体

- `Flow`：流程定义，包含节点、边、版本与来源提示词。
- `Task`：流程解析后的可调度单元，含依赖、状态、执行目标与产出索引。
- `Approval`：敏感动作审批请求与决议。
- `Artifact`：任务产出（文本、结构化数据、文件引用、预览元数据）。
- `DebugInput`：用户追加输入与重试意图。

### 6.1 v0.7 任务来源约束

- 看板展示与新增都基于 Linpo 后端持久化的真实 `Task` 实体。
- OpenClaw `session` 仅作为执行侧上下文，不作为看板任务实体直接映射。
- v0.7 任务接口采用 board 资源风格：`/api/v1/boards/{board_id}/tasks`，默认看板 `board_id=default`。
- `创建流程` 入口迁移到 `/flow` 页面“新建流程”弹窗：需求可空；填写需求时由后端先生成流程草图，再跳转到 `/flow/edit/:flow_id`。
- 流程拆解由 Linpo 后端 `Flow Decomposition Service` 统一提供，后端固定调用 `claw3` 完成“需求 -> 流程节点”的转化。
- 流程编排最小角色包含：`decomposer(claw3)`（流程拆解服务）、`manager agent`（会话与任务分配），并由 `executor agent` 执行节点任务。
- 任务执行闭环采用“事件主链 + 补偿副链”：`task-run event callback` 负责主状态推进，仅在超时场景触发低频补偿巡检。
- 前端不再编辑 `layer`；提交前按 DAG 动态计算拓扑层级并回填 `layer` 兼容字段。
- 任务落库时写入 `requirement_id` / `requirement_title`，用于看板“按需求分列、筛选、删除”操作。

## 7. 成功标准

- 用户可在单页面内完成“描述需求 -> 生成流程 -> 并行执行 -> 审批 -> 查看产出”。
- 流程编辑后的依赖关系可稳定转译为任务队列，无错乱执行顺序。
- 敏感操作不会绕过审批入口。
- 任务卡片可稳定展示文本与文件预览结果。
- 前端可以通过 Tauri 构建产出桌面应用。

若产品边界或成功标准与 `docs/architecture.md` 或 `docs/test-resources.md` 冲突，以 `docs/prd.md` 为准。
