# Linpo PRD

## 1. 产品定义

Linpo 是位于 OpenClaw 与用户之间的人机协作编排交互层，不是 OpenClaw 的替代后端。
OpenClaw 提供 Agent 执行能力，Linpo 负责流程可视化、任务编排、审批与协作体验。

## 2. v0.7 目标

v0.7 目标是打通以下闭环：

`一句话需求 -> 流程图（可编辑）-> DAG 任务队列 -> 看板并行推进 -> 统一审批 -> 结果预览与调试`

产品主工作区收敛为“摘要 + 看板 + 流程列表 + 流程编辑 + 文件”，统一使用顶部导航组织，不再保留旧版 `overview / topology / team / session` 主 IA。

## 3. 界面与路由约束

### 3.1 路由

- 默认登录后进入 `/summary`。
- 访问网站根路径 `/` 时：已登录用户重定向到 `/summary`，未登录用户重定向到 `/landing`。
- v0.7 保留：`/login`、`/landing`、`/summary`、`/kanban`、`/flow/edit/:flow_id`、`/profile`、`/instance-files`；`/flow` 仅保留为兼容重定向入口。
- `/landing` 面向游客可直接访问，不要求登录。
- 登录输入支持“用户名或邮箱”二选一；注册时邮箱为必填项。
- 历史页面路由（`overview/topology/team/session`）不再作为主产品入口。

### 3.2 页面结构

- 落地页：`/landing`，用于价值说明与主入口引导；视觉上突出核心优势，并预留 Image 占位区用于后续产品截图与宣传素材。
- 摘要页：`/summary`，作为审批中心；不再提供独立顶部工具栏，页面主体直接展示 token 消耗趋势曲线、待审批卡片列表与事件流侧栏。
- 摘要页 token 曲线优先展示 OpenClaw 实际 token 消耗；若当前实例或数据源不支持 token 统计，则降级展示任务节点数量随时间变化曲线。
- 摘要页审批卡片默认展示 `blocked_by_approval` 节点，并支持直接执行 `继续` 等审批动作；卡片内不再提供“打开看板”跳转按钮。看板中的节点操作继续保留，二者共享同一后端状态机。
- 摘要页事件流侧栏展示按时间倒序排列的系统事件摘要，至少包含实例、Agent、事件类型、时间与描述。
- 摘要页事件流需提供前端本地关键字筛选能力，并按分页展示；单页最多展示 10 条事件卡片。
- 摘要页事件卡片默认以展开态展示完整描述与实例/Agent 信息，不再提供分类按钮组或“全部展开”主动作。
- 摘要页在移动端改为纵向堆叠布局：统计曲线、审批列表、事件流均需完整可见；事件流筛选条允许横向滑动，避免筛选与分页控件在小屏下挤压内容。
- 摘要页整体宽度与留白策略对齐“文件”页主体内容区：普通桌面保持稳定留白，超宽屏时整体居中且限制最大内容宽度，避免图表与审批/事件区域过度拉伸。
- 主体：看板（默认按状态分列，可切换按 agent/流程分列；列宽固定并支持横向滚动查看）。
- 看板列头支持双击折叠/展开列；折叠后整列收敛为半透明窄列，不再保留列头，仅在顶部展示一个纵向省略号并向下渐变透明，展开后恢复完整列内容。
- 未折叠看板列高度应按内部卡片列表自然包裹；当卡片高度超过当前页面可视高度时，仅列内列表区域滚动，不拉伸整列到统一满高。
- 按 agent 分列时提供“新增 Agent”入口列，支持弹窗创建新的主 Agent 列。
- 支持删除单个需求节点与整组需求节点。
- 顶部工具栏仅保留分列方式与统计信息；状态视图中的“创建任务”入口迁入最左侧 `待确认` 列头。
- 看板主数据（任务状态/卡片字段）通过后端 board SSE 通道实时推送增量更新，避免依赖手动刷新。
- 看板“按状态分列”需在最左侧新增 `待确认` 列作为人工起单入口，随后依次保留 `待调度 / 进行中 / 阻塞 / 待审批 / 失败 / 完成`。
- 看板“按状态分列”的 `待确认` 列头内提供“创建任务”按钮；点击后打开弹窗，包含需求输入与 Agent 指派，仅保留“创建任务”入口。
- 看板“按流程分列”下，每列头部展示流程状态与主动作：`运行中->中断流程`、`阻塞中->继续流程`、`已结束->运行流程`；`删除流程` 不放在看板列头，统一在流程编辑页内处理。
- 顶部导航提供并列入口：`摘要`、`看板`、`流程`、`文件`；点击 `流程` 默认进入“上次访问的流程编辑路由”（缓存），若无缓存则进入 `/flow/edit/new`。
- 顶部导航在移动端必须保持可操作：品牌区、主导航、账户入口位于同一栏时，主导航应支持横向滑动，不允许因按钮挤压导致入口不可见或不可点击。
- 全站主工作区滚动归一到应用壳主容器处理；`body/html` 不再承载页面滚动，避免移动端出现“双滚动容器导致局部无法滑动”问题。
- 顶部导航用户信息下拉菜单保留`消息`入口，点击后弹窗展示“系统消息列表 + 消息详情”，用于接收并确认实例挂载/卸载回执链接。
- 顶部导航用户信息下拉菜单新增`实例`入口，点击后弹窗展示“实例列表 + 单实例信息/拓扑详情”。
- 顶部导航用户信息下拉菜单移除`用户信息`菜单项；新增`账户`菜单项，点击后弹窗展示“左侧侧边栏（基本信息/修改密码/会员）+ 右侧展示区”。
- `账户`弹窗的`基本信息`页中，用户可点击头像下方按钮更换头像，并通过用户名右侧编辑按钮改用户名。
- 顶部导航不再提供独立“实例”入口；实例管理统一迁入用户信息下拉菜单。
- `/profile` 页面保留为兼容入口，不再作为用户主导航路径。
- `/pairing` 页面降级为兼容路由，不作为主导航入口；`/pairing/tutorial` 保留为配对教程页。
- `/instance-files` 为登录后页面，用于“按实例聚合查看任务产出文件 + Agent 文档”；不提供任意系统路径浏览。
- `文件` 页不再提供独立顶部工具栏；实例选择、搜索与刷新动作合并进左侧侧栏头部。
- `文件` 页左侧侧栏改为以“实例名”为根节点的真实路径树；根路径口径固定映射为 `/home/node/.openclaw/workspace/`，叶子节点需明确标注其来源是“流程/节点产物”还是“Agent 文档”。
- `文件` 页桌面端左侧侧栏宽度支持用户手动拖拽调整；右上角不再提供“回看板”功能。
- `文件` 页右侧主内容区需占满侧栏之外的剩余宽度；文件预览内容本身限制最大宽度并在主内容区内水平居中，避免超宽文本或图片贴边。
- `/pairing/tutorial` 必须可匿名访问（不要求登录），避免“未配对实例前无法查看教程”的死锁。
- 若用户访问 `/pairing/tutorial`（漏写 `.md` 后缀），前端应自动重定向到 `/pairing/tutorial.md`，不展示中间提示页。
- 实例拓扑树需支持空态与失败态提示：无 Agent/Session 时给出空态文案，拓扑读取失败时给出错误提示并允许重试。
- `教程链接配对` 标签页提供可复制教程链接（`/pairing/tutorial.md`），用于用户直接转发给自己的 OpenClaw 触发自助挂载/卸载流程。
- 配对教程页面向“仅能与 OpenClaw 对话”的用户，给出最短接入路径：在 OpenClaw 中获取 endpoint/token，再回到 Linpo 完成配对。
- 配对教程页需提供“可直接转发给 OpenClaw 的纯文本指引模板”，至少覆盖 `自助挂载` 与 `自助卸载` 两条链路，并支持一键复制。
- 给 OpenClaw 转发的教程地址必须使用静态 Markdown 资源：`/pairing/tutorial.md`（避免 HTML 页面噪音干扰解析）。
- Agent 自助挂载/卸载改为“回执链接确认”双阶段：OpenClaw 发起 request 后，系统生成确认链接并投递到用户消息中心；用户登录 Linpo 后点击链接确认。
- Agent 自助挂载/卸载的目标用户通过 `email` 唯一定位，不再要求 OpenClaw 在 request 阶段提供 `username`。
- `文件` 页不再保留独立工具栏；移动端同样通过侧栏头部承载实例选择、搜索与刷新动作。
- `看板` 页面工具栏不再限制内容最大宽度：顶部工具栏内容直接铺满可用横向空间，仅保留左右内边距与移动端换行/横滑能力。
- `看板` / `编辑流程` / `文件` 三个主工作页在移动端需遵循统一细节：工具栏允许换行或横向滑动但不得裁掉主动作；内容区优先单列堆叠；页面左右留白收紧；列表/预览/画布等重区域保持独立滚动。
- 看板需按屏宽分三级响应式：
  - 桌面/平板：保持左对齐并允许横向滚动查看多列；
  - 超窄移动端：一次仅展示一列，支持左右手势切换列；
  - 不再为超宽屏单独居中看板轨道，但看板工作区本身仍需占满可用高度。
- 流程列表不再拥有独立页面；草稿/已提交流程列表与“新建”动作统一并入 `编辑流程` 页面左侧侧栏。
- 流程编辑页左侧侧栏顶部仅保留标题与同行右侧的“新建”按钮，不展示额外小字说明；下方承载流程列表，点击流程项可直接切换当前编辑上下文。
- 流程编辑页左侧流程列表仅按 `草稿 / 已提交` 分组渲染；当前打开流程不再单独抽出“当前”分组，而是保留在所属分组内并通过激活态高亮体现。
- 流程编辑页左侧流程列表在各分组内按“最后编辑时间”倒序排序，不得因“当前打开”而额外置顶。
- 点击流程编辑页侧栏中的“新建”按钮，直接创建一个 `未命名流程` 草稿并进入当前编辑页，不再先弹窗收集流程名/需求。
- 新创建的空草稿可随后通过底部悬浮输入框向 `claw3` 发送需求，按实时增量改图方式持续补全节点；流程页规划浮窗分为`手动编辑模式`与`对话自动编辑模式`：折叠态为手动模式，展开消息流后进入自动模式。
- `编辑流程` 页面采用“左侧流程列表侧栏 + 右侧流程画布”工作台结构：不再提供顶部独立工具栏，画布占据主编辑区域并可滚动查看。
- 流程列表项需内嵌编辑入口；当前打开流程的卡片内同时承载主`运行`按钮。`编辑`按钮位于卡片标题同行右端，`运行`按钮位于其下方；点击编辑后弹出流程操作窗口，统一承载`重命名 / 删除 / 运行 / 中断 / 继续`动作。
- `编辑流程` 页面在移动端将左侧流程列表侧栏收纳为抽屉：默认隐藏，仅通过画布内显式入口打开；抽屉内继续复用相同的流程切换与新建能力。
- 移动端流程抽屉打开后需将焦点显式移入当前流程项或抽屉主动作；关闭后焦点返回画布内的“流程列表”触发按钮，避免键盘与辅助技术用户丢失上下文。
- 初次创建流程时，默认流程名为首次发送需求的前 8 个字符加 `...`（超长截断）。
- `编辑流程` 页不再保留画布右上角流程主状态按钮；当前打开流程对应的侧栏卡片内提供主运行入口，位于卡片右侧 `编辑` 按钮下方。
- `编辑流程` 页在移动端不得依赖双击完成核心编辑动作；画布内需提供显式入口至少覆盖：`新建节点`、`编辑已选节点`、`打开流程列表`。
- 单流程即单实例：点击`运行`将该流程加入看板并进入运行态；运行态按钮切换为`中断`，中断后切换为`继续`。
- 运行中的流程冻结编辑；阻塞中的流程可编辑未执行节点并同步回写看板对应节点内容；流程自然结束（成功/失败）后按钮回到`运行`。
- 流程画布继续保留泳道概念，用于给不同节点分配不同 Agent；每个泳道占用一列并承载对应节点。
- 流程画布支持人工编辑：节点/连线均可增删改；节点上下左右各有一个连接点用于连线；双击画布弹窗创建节点，双击节点弹窗编辑节点。
- 移动端保留桌面双击快捷操作，但必须同时提供画布内显式按钮完成节点创建与节点编辑；单击节点用于选中。
- 节点编辑需支持“标题 + 详细描述”，描述用于后续任务执行上下文。
- 连线交互采用“从连接点拖拽到连接点”；渲染时根据节点相对位置自动选择最短接入点组合，而非节点中心连线。
- 不再暴露 L1~Lx 层级编辑；任务拓扑层级由系统在提交前按 DAG 拓扑动态计算，并据此分配到可执行 Agent。
- 节点间数据流通统一约束为“临时文件通道”。
- 品牌区（`LP/灵盘`）支持点击跳转到落地页。
- 流程编辑页左侧流程列表侧栏用于快速切换流程，展示草稿/已提交流程的名称与状态摘要，并直接承载标题区“新建”入口。
- 流程编辑页消息流与对话框回到画布底部作为悬浮窗口；仅保留干净的消息流与输入框，不再展示额外 title/描述文案。
- 流程编辑页底部悬浮消息窗口在焦点位于悬浮对话框或消息流内部时自动展开；展开后即进入`对话自动编辑模式`，画布显示半透明遮罩并禁止手动编辑。收起后回到`手动编辑模式`，只保留一个输入框，placeholder 固定为 `输入您的需求，自动规划流程`。
- 流程编辑页底部悬浮消息窗口折叠态为半透明单输入框，不再额外套外层边框；展开态改为“上方消息流 + 下方输入框”顺序，若暂无历史消息则消息区保持空白。
- 流程编辑页底部悬浮消息窗口展开态需展示消息流与对话框，并在新消息到来或展开时自动滚动到底部；规划消息流使用 SSE 增量展示，发送按钮单独占下一行右侧，左侧以灰色小字展示 `Enter 发送` 与 `Shift+Enter 换行`。消息流视觉上需从底部向上渐变到透明，不额外出现“规划中”等无效提示文案。
- 流程编辑页底部悬浮消息窗口需尽量减少对画布底部的长期占位，不得制造额外底部留白；移动端仅为悬浮窗本身预留最小安全间距。
- 流程图画布需占满除侧栏与悬浮窗口安全间距之外的全部可用空间，避免底部或右侧留下无意义留白。
- 流程编辑页节点状态（`queued/running/blocked_by_approval/failed/completed`）需通过 SSE 实时同步，避免手动刷新后才看到状态变化。
- 流程编辑页键盘契约：`Enter` 发送、`Shift+Enter` 换行；发送后输入框立即清空。
- 流程编辑页发送中状态：保持`对话自动编辑模式`，画布编辑禁用且出现半透明遮罩；浮窗输入区保持只读或禁用，主按钮从`发送`切换为`停止`，直到 planner 会话进入终态（`completed/stopped/failed`）前不得退出自动模式。
- 流程编辑页移除画布右上角悬浮运行按钮；当前流程的侧栏卡片承担“运行”主入口，中断/继续等流程级动作统一收敛到流程列表项的编辑弹窗中。
- 每次发送指令时，前端必须携带当前画布上下文；后端以“节点内 `depends_on` 定义依赖、边由系统派生”的图模型作为唯一真源，前端不得把边作为独立权威数据源。
- 流程规划从“一次返回整图后覆盖画布”升级为“逐节点实时增删改”：用户发送后，前端先拿到 planner session，再通过 SSE 持续接收节点级变更并即时更新画布，不再等待最终 commit 才显示结果。
- 流程规划增量协议以节点为中心：至少支持 `upsert_node` 与 `delete_node` 两类实时操作；`depends_on` 变更视为节点更新的一部分，边始终由前端/后端根据当前节点集即时重算，不单独定义边补丁协议。
- 流程规划 SSE 仍保留快照/重同步能力：当前端漏事件、重连或解析失败时，可请求最新节点快照并重建派生边，随后继续订阅实时增量。
- 流程规划消息流需持久化保存，不得只依赖前端内存；用户消息、planner 发起的节点编辑请求、系统状态变更与失败原因都要进入同一 planner 会话消息流，并可在刷新后恢复。
- 后端发送给 `claw3` 的规划上下文必须混入“历史 planner 消息 + 当前工作流 JSON 快照”；planner 不再一次性回传整图 JSON 覆盖，而是通过 Linpo 提供的单节点 HTTP 编辑接口多次调用 `upsert/delete` 持续改图。
- `claw3` 在完成多次单节点编辑后，需通过 Linpo planner 完成接口提交最终工作流快照并触发后端校验；校验通过后结束会话。前端在会话结束时不再额外等待 commit，因为画布已被实时更新到最终状态。
- planner 会话的结束判定以 Linpo planner session 状态为准，而不是 `flow.generate` HTTP 响应是否已经返回；若 planner 尚未显式 `complete/fail/stop`，前端必须继续保持自动模式遮罩与停止按钮。进入终态后不强制自动收起，用户可点击遮罩返回手动编辑模式。
- 全站输入控件（`input/textarea/select`）在各自容器内必须遵循 `box-sizing: border-box` 与 `max-width: 100%`，不得出现向右溢出容器的布局错误。

## 4. 核心用户行为

1. 用户在看板“按状态分列”的最左侧 `待确认` 列头点击“创建任务”，输入一句话需求并指派 Agent。
2. 若点击“创建任务”，系统直接写入 `queued` 队列并触发调度。
3. 用户在编辑页左侧流程侧栏点击“新建”，系统直接创建一个 `未命名流程` 草稿并切换到该草稿。
4. 用户随后可在编辑页画布底部悬浮消息窗口输入需求，流程拆解固定使用 `claw3`；系统携带“当前画布上下文 + 指令”调用后端拆解服务。
5. 后端先写入持久化 planner 会话与首条用户消息，再把“历史消息 + 当前工作流 JSON + 本次需求”发送给 `claw3`。
6. `claw3` 在同一会话中通过 Linpo 提供的 planner HTTP 单节点编辑接口多次调用 `upsert_node/delete_node`，Linpo 每次都立刻持久化消息与节点快照，并通过 SSE 推给前端；前端边收边改图并在同一浮窗内展示消息流。
7. 会话进行中，浮窗主按钮切换为`停止`，流程页保持对话自动编辑模式，画布显示遮罩并禁编；若用户点击停止，后端中断 planner 会话并把状态写入消息流。
8. `claw3` 完成最终校验后调用完成接口结束会话；此时前端恢复`发送`按钮并保留自动模式消息流，用户可继续查看规划过程，随后点击遮罩退回手动编辑模式。
9. 用户可在编辑页左侧流程列表侧栏中切换不同流程，并在右侧画布中创建节点、编辑节点、拖线连接节点；桌面支持双击快捷操作，移动端通过画布内显式按钮完成节点创建/编辑。
10. 用户在当前打开流程的侧栏卡片上点击“运行”，系统按当前节点/连接关系做 DAG 拓扑计算后将该流程加入看板 `queued` 队列并进入流程运行态。
11. 调度器从 `queued` 队列取一个可执行任务分配给 agent；任务执行完成后再取下一个。
12. agent 通过 `task-run events` 回调上报 `started/progress/completed/failed/need_approval`，后端按事件推进状态机。
13. 调度阶段遇到敏感操作，统一进入审批状态队列，用户在看板节点或流程主动作中继续处理。
14. 每个任务卡片可查看执行日志、消息产出与文件预览。
15. 任务卡片弹窗为三标签页：`基本信息 / 执行流程 / 任务产出`，降低信息拥挤；弹窗默认打开`基本信息`标签；`执行流程`先加载任务节点 `execution_session_key` 对应 history，再通过 realtime 增量更新，不使用轮询刷新。
16. 看板列表本身通过 `board realtime` 增量更新任务变更（新增/状态推进/删除），任务卡片与弹窗内容应随事件即时同步。
17. `基本信息`页任务控制按钮按状态差异化展示：`running`展示`中断`，`blocked_by_approval`展示`继续`，其余状态显示对应可用动作或不展示控制按钮。
18. 任务进入终态（`completed/failed/blocked_by_approval`）后不自动切换标签页，保持当前/默认的`基本信息`视图。
19. “任务产出”是用于交接的文件资源，来源由 Agent 显式上报（`artifact` 回调）决定，不从普通消息文本中推断；文件按格式支持点击预览与下载（如 JSON 折叠结构、图片/PDF/音视频内嵌预览）。
20. 节点间数据交换通过临时文件传递，避免上下游节点共享内存上下文。
21. 用户可在流程页人工新增/删除节点、修改节点属性、创建/删除连接，再运行流程到看板；运行中冻结编辑，阻塞后可编辑未执行节点并同步看板。
22. 用户在“按流程分列”下可通过列头主动作驱动流程状态机（运行/中断/继续）；删除流程会先中断再删除整组节点。
23. 用户可切换到“摘要”页集中处理待审批任务，在审批卡片列表中完成继续操作，并结合右侧事件流理解上下文。
24. 摘要页顶部统计曲线默认展示最近时间窗口内的 token 消耗趋势；若实例统计暂不可用，则退化为任务节点数趋势。
25. 用户可在摘要页对事件流按关键字筛选，并通过分页浏览最近事件；事件卡片默认展示完整上下文。
26. 首次接入用户可匿名进入 `/pairing/tutorial` 按步骤获取 OpenClaw endpoint/token，再在`用户信息下拉 -> 实例`弹窗中完成配对并设置当前实例。
27. 仅能与 OpenClaw 对话的用户，可让 agent 按教程发起“自助挂载请求”，系统返回并投递回执确认链接。
28. 用户登录 Linpo 后在“消息”中打开回执链接并确认，完成实例挂载或卸载。
29. 用户可在“用户信息”页面更新头像与密码；头像与密码更新后即刻生效且可在后续登录中验证。
30. 用户可在“用户信息”页面看到会员充值入口（支付宝/PayPal），当前阶段展示“未开通”状态与后续提示。
31. 用户可在“实例文件”页面按实例筛选任务产出文件，进行预览与下载，并可跳转关联任务定位上下文。
32. 用户可在“实例文件”页面查看 OpenClaw Agent 工作区中的白名单文档（如 `AGENTS.md`、`SOUL.md`、`IDENTITY.md`、`USER.md`、`MEMORY.md`），用于理解 Agent 设定与长期记忆。

## 5. 功能范围

**In-Scope（v0.7）**

- 句子到流程图生成（调用 OpenClaw）
- 流程图手动编辑
- DAG 依赖解析与并行子任务入板
- 看板视图切换（状态/agent/流程）
- 流程节点删除（单节点/整组）
- 敏感操作统一审批
- 任务卡片结果查看与文件预览
- 卡片字段可扩展数据结构（支持异构字段）
- 摘要页审批中心（待审批卡片 + 事件流侧栏 + token 消耗趋势）
- 默认以 `claw1` 作为联调后端
- OpenClaw 配对能力（主入口位于`用户信息下拉 -> 实例`弹窗，支持 `claw2` 作为用户自有实例接入）与配对教程页
- 实例详情支持树形拓扑展示（`Instance -> Agent -> Session`）。
- 实例文件页：按实例聚合任务产物文件与 Agent 文档，支持搜索、预览、下载与关联任务定位；左侧侧栏顶部依次承载“实例选择下拉+右侧刷新按钮”与搜索框，下方以“实例名”为根节点的文件树承载资源导航，桌面端支持拖拽调宽，右侧展示居中预览。
- 支持 `Token` 与 `配对码` 两种配对方式；配对码方式为“用户输入短码，后端解析并完成实例校验/创建”。
- 支持 Agent 自助挂载/卸载（`request -> receipt link -> login confirm` 双阶段）。
- 支持用户信息页：头像修改、密码修改、会员充值入口占位（支付宝/PayPal）。
- 支持 Tauri 构建

**Out-of-Scope（v0.7）**

- 模板市场（Marketplace）
- agent 拓扑配置页

以上能力延后到 v0.8。

## 6. 关键实体

- `Flow`：流程定义，包含节点、边、版本与来源提示词。
- `Task`：流程解析后的可调度单元，含依赖、状态、执行目标与产出索引。
- `Approval`：敏感动作审批请求与决议。
- `Artifact`：任务产出（文本、结构化数据、文件引用、预览元数据）。
- `DebugInput`：用户追加输入与重试意图。
- `PairingReceipt`：Agent 自助挂载/卸载回执（一次性、短时有效、需登录确认）。
- `UserMessage`：投递到用户消息中心的系统消息，支持携带可点击回执链接。
- `SummaryMetric`：摘要页顶部统计曲线数据点，优先表示 token 消耗，兜底为任务节点数量。

### 6.1 v0.7 任务来源约束

- 看板展示与新增都基于 Linpo 后端持久化的真实 `Task` 实体。
- OpenClaw `session` 仅作为执行侧上下文，不作为看板任务实体直接映射。
- v0.7 任务接口采用 board 资源风格：`/api/v1/boards/{board_id}/tasks`，默认看板 `board_id=default`。
- 流程创建入口收敛到流程编辑页左侧侧栏“新建”按钮：点击即生成空白草稿并切换到 `/flow/edit/:flow_id`，后续需求输入统一通过流程页底部规划浮窗完成。
- 流程拆解由 Linpo 后端 `Flow Decomposition Service` 统一提供，后端固定调用 `claw3` 完成“需求 -> 流程节点”的转化；`flow.generate` 必须显式把 planner 目标解析为 `claw3`，不得回退到其他默认 agent。
- 流程页浮窗消息流通过后端 SSE 通道订阅 `planner_session_key` 对应会话；消息真源是 Linpo 持久化的 planner session，而不是 `flow.generate` 响应体内的静态 `messages` 数组或 OpenClaw `chat.history` 的瞬时结果。前端按 `planner_messages_updated / planner_nodes_patched / planner_snapshot_updated / planner_session_updated` 处理增量。
- planner session 需要由 Linpo 后端持久化保存消息、当前节点快照、修订号与会话状态，前端刷新后可按 `planner_session_key` 恢复消息流与最新草稿。
- 流程草稿（未提交流程）必须落库到 Linpo 后端，不得仅依赖浏览器本地存储；前端本地缓存仅作临时容错，后端草稿记录为真源。
- 流程拆解图模型以 `nodes[].depends_on` 为唯一依赖来源；边是派生视图，不是 planner 协议的独立写入对象。
- 流程拆解协议升级为“增量改图”：planner 在 session 中持续输出节点级操作流，Linpo 后端维护该 session 对应的流程草稿快照，并通过 SSE 向前端推送实时操作与最新快照。
- planner 的增量改图入口从“assistant 直接回整图 JSON”进一步收敛为“planner 通过 Linpo 内部 HTTP 接口单节点编辑”：至少支持 `upsert_node/delete_node/complete/fail/stop`，每次请求都要写入会话消息流并更新最新草稿快照。
- 流程拆解提示词需显式鼓励并行：优先识别可独立子任务并拆为并行分支，鼓励执行侧通过 subagent 并发完成可拆分节点。
- 流程拆解提示词需显式约束“文件交接可访问性”：节点描述中的输出策略必须与 Linpo 产物沙箱一致；可预览、可下载的产物路径统一限制在 `/tmp/linpo/**`。
- 流程编排最小角色包含：`decomposer(claw3)`（流程拆解服务）、`manager agent`（会话与任务分配），并由 `executor agent` 执行节点任务。
- 任务执行闭环采用“事件主链 + 补偿副链”：`task-run event callback` 负责主状态推进；超时补偿巡检用于把 stale `running` 任务转为 `failed(stale_timeout)`，当前实现由任务读取链路触发（非独立后台定时任务）。
- 任务投放提示词需包含“路径不可访问失败”约束：优先写入指定 `temp_output_path`；若受沙箱限制不可写，不得静默回退到其他目录并宣告 `completed`，必须回调 `failed` 并写明不可访问路径与原因。
- 前端不再编辑 `layer`；提交前按 DAG 动态计算拓扑层级并回填 `layer` 兼容字段。
- 任务落库时写入 `requirement_id` / `requirement_title`，用于看板“按流程分列、删除整组流程节点”与流程名展示。
- 实例文件访问边界：
  - 任务产物侧只允许访问“任务显式上报或任务元数据声明”且位于 `/tmp/linpo/**` 的文件路径（如 `artifact`、`temp_output_path`），不开放任意主机路径浏览。
  - Agent 文档侧只允许访问 OpenClaw `agents.files.*` 白名单文档，不开放任意工作区路径浏览。
- 实例文件页展示约束：
  - 文件树的根节点文案使用实例名代替 `workspace`；其子节点仍映射真实工作区目录结构并支持递归展开。
  - 左侧文件树叶子节点采用紧凑列表样式，仅展示 `[icon][文件名]`；`配置/产出`、流程、节点、Agent、路径、时间等附加信息统一移到右侧预览区展示。
  - 右侧预览头部仅保留当前文件信息与下载动作，不再提供“回看板”快捷入口。
- 摘要页统计边界：
  - 若实例可用 OpenClaw `usage.cost`，则按实例聚合最近窗口内的 token 日序列并展示。
  - 若 token 统计不可用，则摘要页允许回退为 Linpo 本地任务节点数时间序列，但前端需显式展示当前指标类型。

## 7. 成功标准

- 用户可在单页面内完成“描述需求 -> 生成流程 -> 并行执行 -> 审批 -> 查看产出”。
- 流程编辑后的依赖关系可稳定转译为任务队列，无错乱执行顺序。
- 敏感操作不会绕过审批入口。
- 任务卡片可稳定展示文本与文件预览结果。
- 前端可以通过 Tauri 构建产出桌面应用。

若文档冲突涉及产品边界、交互口径或成功标准，以 `docs/prd.md` 为准；若 `docs/prd.md` 未明示实现细节，则以 `docs/architecture.md` 为准；`docs/test-resources.md` 仅承载测试与联调资源，不单独覆盖前两者。
