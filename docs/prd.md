# Linpo PRD

## 1. 产品定义

Linpo 是位于 OpenClaw 与用户之间的人机协作编排交互层，不是 OpenClaw 的替代后端。
OpenClaw 提供 Agent 执行能力，Linpo 负责流程可视化、任务编排、审批与协作体验。

## 2. v0.7 目标

v0.7 目标是打通以下闭环：

`一句话需求 -> 流程图（可编辑）-> DAG 任务队列 -> 看板并行推进 -> 统一审批 -> 结果预览与调试`

产品主工作区收敛为“摘要 + 看板 + 流程列表 + 流程编辑 + 文件”，统一使用顶部导航与贴顶工具栏组织，不再保留旧版 `overview / topology / team / session` 主 IA。

## 3. 界面与路由约束

### 3.1 路由

- 默认登录后进入 `/kanban`。
- v0.7 保留：`/login`、`/landing`、`/summary`、`/kanban`、`/flow/edit/:flow_id`、`/profile`、`/instance-files`；`/flow` 仅保留为兼容重定向入口。
- `/landing` 面向游客可直接访问，不要求登录。
- 登录输入支持“用户名或邮箱”二选一；注册时邮箱为必填项。
- 历史页面路由（`overview/topology/team/session`）不再作为主产品入口。

### 3.2 页面结构

- 落地页：`/landing`，用于价值说明与主入口引导；视觉上突出核心优势，并预留 Image 占位区用于后续产品截图与宣传素材。
- 摘要页：`/summary`，作为审批中心；顶部展示 token 消耗趋势曲线，主体左侧展示待审批卡片列表，右侧展示事件流侧栏。
- 摘要页 token 曲线优先展示 OpenClaw 实际 token 消耗；若当前实例或数据源不支持 token 统计，则降级展示任务节点数量随时间变化曲线。
- 摘要页审批卡片默认展示 `blocked_by_approval` 节点，并支持直接执行 `继续` 等审批动作；看板中的节点操作继续保留，二者共享同一后端状态机。
- 摘要页事件流侧栏展示按时间倒序排列的系统事件摘要，至少包含实例、Agent、事件类型、时间与描述。
- 摘要页事件流需提供前端本地筛选能力，最少支持：`全部 / 审批 / 执行 / 拓扑 / Agent / 异常` 六类，并提供关键字筛选。
- 摘要页事件卡片默认可折叠展示，折叠态只保留时间、类型与一行摘要；展开后展示完整描述与实例/Agent 信息。
- 摘要页在移动端改为纵向堆叠布局：统计曲线、审批列表、事件流均需完整可见；事件流筛选条允许横向滑动，避免工具栏或侧栏在小屏下挤压内容。
- 摘要页整体宽度与留白策略对齐“文件”页：工具栏与主体内容均采用相同页面壳宽度与边距，普通桌面保持稳定留白，超宽屏时整体居中且限制最大内容宽度，避免图表与审批/事件区域过度拉伸。
- 主体：看板（默认按状态分列，可切换按 agent/流程分列；列宽固定并支持横向滚动查看）。
- 看板列头支持双击折叠/展开列；折叠后整列收敛为半透明窄列，不再保留列头，仅在顶部展示一个纵向省略号并向下渐变透明，展开后恢复完整列内容。
- 未折叠看板列高度应按内部卡片列表自然包裹；当卡片高度超过当前页面可视高度时，仅列内列表区域滚动，不拉伸整列到统一满高。
- 按 agent 分列时提供“新增 Agent”入口列，支持弹窗创建新的主 Agent 列。
- 支持删除单个需求节点与整组需求节点。
- 顶部工具栏：`➕任务` 与分列方式（左侧展示流程数量统计）。
- 看板主数据（任务状态/卡片字段）通过后端 board SSE 通道实时推送增量更新，避免依赖手动刷新。
- 看板“按状态分列”需包含阻塞列（用于展示被中断/阻断的节点），并保留待审批列。
- 看板“按流程分列”下，每列头部展示流程状态与主动作：`运行中->中断流程`、`阻塞中->继续流程`、`已结束->运行流程`；`删除流程` 不放在看板列头，统一在流程编辑页内处理。
- 点击 `➕任务` 打开弹窗，包含需求输入与 Agent 指派；弹窗提供“创建任务/创建流程”双入口。
- 顶部导航提供并列入口：`摘要`、`看板`、`流程`、`文件`；点击 `流程` 默认进入“上次访问的流程编辑路由”（缓存），若无缓存则进入 `/flow/edit/new`。
- 顶部导航在移动端必须保持可操作：品牌区、主导航、账户入口位于同一栏时，主导航应支持横向滑动，不允许因按钮挤压导致入口不可见或不可点击。
- 全站主工作区滚动归一到应用壳主容器处理；`body/html` 不再承载页面滚动，避免移动端出现“双滚动容器导致局部无法滑动”问题。
- 顶部导航用户信息下拉菜单保留`消息`入口，点击后弹窗展示“系统消息列表 + 消息详情”，用于接收并确认实例挂载/卸载回执链接。
- 顶部导航用户信息下拉菜单新增`实例`入口，点击后弹窗展示“实例列表 + 单实例信息/拓扑详情”。
- 顶部导航用户信息下拉菜单移除`用户信息`菜单项；新增`账户`菜单项，点击后弹窗展示“左侧侧边栏（基本信息/修改密码/会员）+ 右侧展示区”。
- `账户`弹窗的`基本信息`页中，用户可点击头像下方按钮更换头像，并通过用户名右侧编辑按钮改用户名。
- 顶部导航不再提供独立“实例”入口；实例管理统一迁入用户信息下拉菜单。
- `/profile` 页面保留为兼容入口，不再作为用户主导航路径。
- `/pairing` 页面降级为兼容路由，不作为主导航入口；`/pairing/tutorial` 保留为配对教程页。
- `/instance-files` 为登录后页面，用于“按实例聚合查看任务产出文件 + Agent 文档”；不提供任意系统路径浏览。
- `/pairing/tutorial` 必须可匿名访问（不要求登录），避免“未配对实例前无法查看教程”的死锁。
- 若用户访问 `/pairing/tutorial`（漏写 `.md` 后缀），前端应自动重定向到 `/pairing/tutorial.md`，不展示中间提示页。
- 实例拓扑树需支持空态与失败态提示：无 Agent/Session 时给出空态文案，拓扑读取失败时给出错误提示并允许重试。
- `教程链接配对` 标签页提供可复制教程链接（`/pairing/tutorial.md`），用于用户直接转发给自己的 OpenClaw 触发自助挂载/卸载流程。
- 配对教程页面向“仅能与 OpenClaw 对话”的用户，给出最短接入路径：在 OpenClaw 中获取 endpoint/token，再回到 Linpo 完成配对。
- 配对教程页需提供“可直接转发给 OpenClaw 的纯文本指引模板”，至少覆盖 `自助挂载` 与 `自助卸载` 两条链路，并支持一键复制。
- 给 OpenClaw 转发的教程地址必须使用静态 Markdown 资源：`/pairing/tutorial.md`（避免 HTML 页面噪音干扰解析）。
- Agent 自助挂载/卸载改为“回执链接确认”双阶段：OpenClaw 发起 request 后，系统生成确认链接并投递到用户消息中心；用户登录 Linpo 后点击链接确认。
- Agent 自助挂载/卸载的目标用户通过 `email` 唯一定位，不再要求 OpenClaw 在 request 阶段提供 `username`。
- `看板` / `编辑流程` 两个主工作页统一使用贴顶的扁平工具栏视觉风格。
- `摘要` / `编辑流程` / `文件` 三个主工作页的工具栏宽度策略需统一：工具栏与主体内容容器在普通桌面保持一致边距，超宽屏时居中并受统一 `max-width` 约束，移动端收紧左右留白。
- `看板` 页面工具栏不再限制内容最大宽度：顶部工具栏内容直接铺满可用横向空间，仅保留左右内边距与移动端换行/横滑能力。
- `看板` / `编辑流程` / `文件` 三个主工作页在移动端需遵循统一细节：工具栏允许换行或横向滑动但不得裁掉主动作；内容区优先单列堆叠；页面左右留白收紧；列表/预览/画布等重区域保持独立滚动。
- 看板需按屏宽分三级响应式：
  - 桌面/平板：保持左对齐并允许横向滚动查看多列；
  - 超窄移动端：一次仅展示一列，支持左右手势切换列；
  - 不再为超宽屏单独居中看板轨道，但看板工作区本身仍需占满可用高度。
- 流程列表不再拥有独立页面；草稿/已提交流程列表、筛选、排序与“新建流程”动作统一并入 `编辑流程` 页面左侧侧栏。
- 流程编辑页左侧侧栏顶部承载流程筛选/排序与新建入口，下方承载流程列表；点击流程项可直接切换当前编辑上下文。
- 流程编辑页左侧侧栏中的筛选/排序条件需在本地持久化，用户切换流程、刷新页面或重新进入编辑页后默认恢复上次使用的条件。
- 流程编辑页左侧流程列表需按 `当前 / 草稿 / 已提交` 分组渲染；若当前流程同时属于草稿或已提交，也只在“当前”分组展示一次，避免重复占位。
- 点击流程编辑页侧栏中的“新建流程”按钮，先弹窗填写流程名/需求（均可为空）；流程拆解固定使用 `claw3`（后续通过配置改写）。
- 若需求为空：直接创建空流程并进入当前编辑页；若填写了需求：弹出“生成中”提示，后端完成拆解后自动切换到新流程并载入流程草图。
- `编辑流程` 页面采用“顶部独立工具栏 + 主体左右工作台”结构：左侧为流程列表侧栏，右侧为流程画布；画布占据主编辑区域并可滚动查看。
- `编辑流程` 页面在移动端将左侧流程列表侧栏收纳为抽屉：默认隐藏，仅通过工具栏显式打开；抽屉内继续复用相同的流程切换、筛选、排序与新建能力。
- 移动端流程抽屉打开后需将焦点显式移入当前流程项或抽屉主动作；关闭后焦点返回工具栏的“流程列表”按钮，避免键盘与辅助技术用户丢失上下文。
- `编辑流程` 页面顶部工具栏不再限制内容最大宽度：工具栏内容直接铺满可用横向空间，仅保留页面内边距。
- `编辑流程` 页工具栏左侧为目录结构：`流程 / {当前流程名}`；点击 `流程` 打开或聚焦左侧流程侧栏，点击 `{当前流程名}` 打开流程详情卡片并支持重命名。
- 初次创建流程时，默认流程名为首次发送需求的前 8 个字符加 `...`（超长截断）。
- `编辑流程` 页工具栏右侧仅保留流程主状态按钮：`运行 / 中断 / 继续`。
- `编辑流程` 页在移动端不得依赖双击完成核心编辑动作；工具栏需提供显式入口至少覆盖：`新建节点`、`编辑已选节点`。
- 单流程即单实例：点击`运行`将该流程加入看板并进入运行态；运行态按钮切换为`中断`，中断后切换为`继续`。
- 运行中的流程冻结编辑；阻塞中的流程可编辑未执行节点并同步回写看板对应节点内容；流程自然结束（成功/失败）后按钮回到`运行`。
- 流程画布采用横向多泳道布局：每个泳道占用一列，顶部冻结一行显示泳道标题。
- 流程画布支持人工编辑：节点/连线均可增删改；节点上下左右各有一个连接点用于连线；双击画布弹窗创建节点，双击节点弹窗编辑节点。
- 移动端保留桌面双击快捷操作，但必须同时提供工具栏显式按钮完成节点创建与节点编辑；单击节点用于选中。
- 节点编辑需支持“标题 + 详细描述”，描述用于后续任务执行上下文。
- 双击顶部空白区可创建泳道（可指定泳道名称与委派 Agent），双击泳道标题可修改泳道名称与委派 Agent。
- 节点创建在双击位置并归属所在泳道；泳道宽度根据内部节点占用自适应扩展，右侧泳道顺延。
- 节点拖拽支持跨泳道移动，跨列后自动切换节点归属泳道与执行 Agent。
- 连线交互采用“从连接点拖拽到连接点”；渲染时根据节点相对位置自动选择最短接入点组合，而非节点中心连线。
- 不再暴露 L1~Lx 层级编辑；任务拓扑层级由系统在提交前按 DAG 拓扑动态计算，并据此分配到可执行 Agent。
- 节点间数据流通统一约束为“临时文件通道”。
- 品牌区（`LP/灵盘`）支持点击跳转到落地页。
- 流程编辑页左侧流程列表侧栏用于快速切换流程，展示草稿/已提交流程的名称与状态摘要，并直接承载筛选、排序与新建入口。
- 流程编辑页消息流与对话框回到画布底部作为悬浮窗口；窗口内上方展示流程规划消息流，下方为输入框与发送按钮。
- 流程编辑页底部悬浮消息窗口需保留足够宽度与高度，避免遮挡核心画布区域；移动端可收窄为贴底浮层。
- 流程编辑页底部悬浮消息窗口在移动端需支持“折叠/展开”两态：折叠态仅保留标题与最近状态摘要，展开后展示完整消息流与输入框；桌面端保持默认展开。
- 折叠态摘要需优先展示最近一条规划消息或当前未发送草稿，而不是仅展示占位文案，帮助用户在不展开浮窗的情况下判断当前规划进度。
- 流程编辑页节点状态（`queued/running/blocked_by_approval/failed/completed`）需通过 SSE 实时同步，避免手动刷新后才看到状态变化。
- 流程编辑页键盘契约：`Enter` 发送、`Shift+Enter` 换行；发送后输入框立即清空。
- 流程编辑页发送中状态：画布编辑与发送按钮均禁用，发送按钮文案显示“正在规划...”。
- 每次发送指令时，前端必须携带当前画布（节点/连线）作为上下文，便于后端在现有流程上增量修改。

## 4. 核心用户行为

1. 用户在看板点击 `➕任务`，输入一句话需求并指派 Agent。
2. 若点击“创建任务”，系统直接写入 `queued` 队列并触发调度。
3. 用户在编辑页左侧流程侧栏点击“新建流程”，可选填写流程名与需求；流程拆解固定使用 `claw3`。
4. 若需求为空则直接创建空流程；若填写需求则后端拆解并生成流程草图后自动切换到该编辑页。
5. 用户可在编辑页左侧流程列表侧栏中筛选、排序和切换不同流程，并在右侧画布中创建节点、编辑节点、拖线连接节点、编辑泳道标题与委派 Agent；桌面支持双击快捷操作，移动端通过工具栏显式按钮完成节点创建/编辑。
6. 用户可在编辑页画布底部悬浮消息窗口输入指令，系统携带“当前画布上下文 + 指令”调用后端拆解服务，返回新的流程草图覆盖画布，并在同一浮窗内展示规划消息流。
7. 用户点击“运行”，系统按当前节点/连接关系做 DAG 拓扑计算后将该流程加入看板 `queued` 队列并进入流程运行态。
8. 调度器从 `queued` 队列取一个可执行任务分配给 agent；任务执行完成后再取下一个。
9. agent 通过 `task-run events` 回调上报 `started/progress/completed/failed/need_approval`，后端按事件推进状态机。
10. 调度阶段遇到敏感操作，统一进入审批状态队列，用户在看板节点或流程主动作中继续处理。
11. 每个任务卡片可查看执行日志、消息产出与文件预览。
12. 任务卡片弹窗为三标签页：`基本信息 / 执行流程 / 任务产出`，降低信息拥挤；弹窗默认打开`基本信息`标签；`执行流程`先加载任务节点 `execution_session_key` 对应 history，再通过 realtime 增量更新，不使用轮询刷新。
13. 看板列表本身通过 `board realtime` 增量更新任务变更（新增/状态推进/删除），任务卡片与弹窗内容应随事件即时同步。
14. `基本信息`页任务控制按钮按状态差异化展示：`running`展示`中断`，`blocked_by_approval`展示`继续`，其余状态显示对应可用动作或不展示控制按钮。
15. 任务进入终态（`completed/failed/blocked_by_approval`）后不自动切换标签页，保持当前/默认的`基本信息`视图。
16. “任务产出”是用于交接的文件资源，来源由 Agent 显式上报（`artifact` 回调）决定，不从普通消息文本中推断；文件按格式支持点击预览与下载（如 JSON 折叠结构、图片/PDF/音视频内嵌预览）。
17. 节点间数据交换通过临时文件传递，避免上下游节点共享内存上下文。
18. 用户可在流程页人工新增/删除节点、修改节点属性、创建/删除连接，再运行流程到看板；运行中冻结编辑，阻塞后可编辑未执行节点并同步看板。
19. 用户在“按流程分列”下可通过列头主动作驱动流程状态机（运行/中断/继续）；删除流程会先中断再删除整组节点。
20. 用户可切换到“摘要”页集中处理待审批任务，在审批卡片列表中完成继续操作，并结合右侧事件流理解上下文。
21. 摘要页顶部统计曲线默认展示最近时间窗口内的 token 消耗趋势；若实例统计暂不可用，则退化为任务节点数趋势。
22. 用户可在摘要页对事件流按类别或关键字筛选，并按需展开单条事件查看完整上下文；移动端下筛选条可横向滚动，事件区维持独立滚动。
22. 首次接入用户可匿名进入 `/pairing/tutorial` 按步骤获取 OpenClaw endpoint/token，再在`用户信息下拉 -> 实例`弹窗中完成配对并设置当前实例。
23. 仅能与 OpenClaw 对话的用户，可让 agent 按教程发起“自助挂载请求”，系统返回并投递回执确认链接。
24. 用户登录 Linpo 后在“消息”中打开回执链接并确认，完成实例挂载或卸载。
25. 用户可在“用户信息”页面更新头像与密码；头像与密码更新后即刻生效且可在后续登录中验证。
26. 用户可在“用户信息”页面看到会员充值入口（支付宝/PayPal），当前阶段展示“未开通”状态与后续提示。
27. 用户可在“实例文件”页面按实例筛选任务产出文件，进行预览与下载，并可跳转关联任务定位上下文。
28. 用户可在“实例文件”页面查看 OpenClaw Agent 工作区中的白名单文档（如 `AGENTS.md`、`SOUL.md`、`IDENTITY.md`、`USER.md`、`MEMORY.md`），用于理解 Agent 设定与长期记忆。

## 5. 功能范围

**In-Scope（v0.7）**

- 句子到流程图生成（调用 OpenClaw）
- 流程图手动编辑
- DAG 依赖解析与并行子任务入板
- 看板视图切换（状态/agent/流程）
- 流程节点删除（单节点/整组）
- 敏感操作统一审批
- 任务卡片结果查看与文件预览
- 卡片字段可扩展数据结构（支持异构字段）
- 摘要页审批中心（待审批卡片 + 事件流侧栏 + token 消耗趋势）
- 默认以 `claw1` 作为联调后端
- OpenClaw 配对能力（主入口位于`用户信息下拉 -> 实例`弹窗，支持 `claw2` 作为用户自有实例接入）与配对教程页
- 实例详情支持树形拓扑展示（`Instance -> Agent -> Session`）。
- 实例文件页：按实例聚合任务产物文件与 Agent 文档，支持搜索、预览、下载、回到关联任务。
- 支持 `Token` 与 `配对码` 两种配对方式；配对码方式为“用户输入短码，后端解析并完成实例校验/创建”。
- 支持 Agent 自助挂载/卸载（`request -> receipt link -> login confirm` 双阶段）。
- 支持用户信息页：头像修改、密码修改、会员充值入口占位（支付宝/PayPal）。
- 支持 Tauri 构建

**Out-of-Scope（v0.7）**

- 模板市场（Marketplace）
- agent 拓扑配置页

以上能力延后到 v0.8。

## 6. 关键实体

- `Flow`：流程定义，包含节点、边、版本与来源提示词。
- `Task`：流程解析后的可调度单元，含依赖、状态、执行目标与产出索引。
- `Approval`：敏感动作审批请求与决议。
- `Artifact`：任务产出（文本、结构化数据、文件引用、预览元数据）。
- `DebugInput`：用户追加输入与重试意图。
- `PairingReceipt`：Agent 自助挂载/卸载回执（一次性、短时有效、需登录确认）。
- `UserMessage`：投递到用户消息中心的系统消息，支持携带可点击回执链接。
- `SummaryMetric`：摘要页顶部统计曲线数据点，优先表示 token 消耗，兜底为任务节点数量。

### 6.1 v0.7 任务来源约束

- 看板展示与新增都基于 Linpo 后端持久化的真实 `Task` 实体。
- OpenClaw `session` 仅作为执行侧上下文，不作为看板任务实体直接映射。
- v0.7 任务接口采用 board 资源风格：`/api/v1/boards/{board_id}/tasks`，默认看板 `board_id=default`。
- `创建流程` 入口迁移到流程编辑页左侧侧栏中的“新建流程”弹窗：需求可空；填写需求时由后端先生成流程草图，再切换到 `/flow/edit/:flow_id`。
- 流程拆解由 Linpo 后端 `Flow Decomposition Service` 统一提供，后端固定调用 `claw3` 完成“需求 -> 流程节点”的转化。
- 流程拆解提示词需显式鼓励并行：优先识别可独立子任务并拆为并行分支，鼓励执行侧通过 subagent 并发完成可拆分节点。
- 流程拆解提示词需显式约束“文件交接可访问性”：节点描述需包含可访问输出策略，若默认临时路径不可访问，需在节点说明中明确替代输出与回传方式。
- 流程编排最小角色包含：`decomposer(claw3)`（流程拆解服务）、`manager agent`（会话与任务分配），并由 `executor agent` 执行节点任务。
- 任务执行闭环采用“事件主链 + 补偿副链”：`task-run event callback` 负责主状态推进，仅在超时场景触发低频补偿巡检。
- 任务投放提示词需包含“路径不可访问兜底”：优先写入指定 `temp_output_path`；若受沙箱限制不可写，必须写入可访问工作目录并在 `completed` 事件 `artifact/message` 中同时回传实际路径与原因。
- 前端不再编辑 `layer`；提交前按 DAG 动态计算拓扑层级并回填 `layer` 兼容字段。
- 任务落库时写入 `requirement_id` / `requirement_title`，用于看板“按流程分列、删除整组流程节点”与流程名展示。
- 实例文件访问边界：
  - 任务产物侧只允许访问“任务显式上报或任务元数据声明”的文件路径（如 `artifact`、`temp_output_path`），不开放任意主机路径浏览。
  - Agent 文档侧只允许访问 OpenClaw `agents.files.*` 白名单文档，不开放任意工作区路径浏览。
- 摘要页统计边界：
  - 若实例可用 OpenClaw `usage.cost`，则按实例聚合最近窗口内的 token 日序列并展示。
  - 若 token 统计不可用，则摘要页允许回退为 Linpo 本地任务节点数时间序列，但前端需显式展示当前指标类型。

## 7. 成功标准

- 用户可在单页面内完成“描述需求 -> 生成流程 -> 并行执行 -> 审批 -> 查看产出”。
- 流程编辑后的依赖关系可稳定转译为任务队列，无错乱执行顺序。
- 敏感操作不会绕过审批入口。
- 任务卡片可稳定展示文本与文件预览结果。
- 前端可以通过 Tauri 构建产出桌面应用。

若产品边界或成功标准与 `docs/architecture.md` 或 `docs/test-resources.md` 冲突，以 `docs/prd.md` 为准。
